# CLAUDE.md — `src/mail`

Каркас письма — **единственная точка выхода письма из API**, обязателен для всех
фич. Правила приложения — `../../CLAUDE.md`. Решения — `docs/research/emails.md`
(снапшот на 03.08.2026), отступления от него — `docs/decisions.md` (03.08.2026).

Отправка только через `MailService.send()`. `MailModule` глобальный и
экспортирует один этот сервис — там же будут лимиты частоты, когда у требования
появится владелец.

## Контракт отправки

Результат различает промис: вернулся — транспорт принял письмо, иначе
`MailCompositionError` (не собралось) или `MailDeliveryError` (не доставилось).
«Тихого успеха» не бывает, проверять в ответе нечего.

## Сборка письма

- **Ссылка прекращения писем — обязательный вход** (`unsubscribePath`): тип не
  даёт её опустить, и та же ссылка уходит в
  `List-Unsubscribe`/`List-Unsubscribe-Post`.
- **Абсолютный адрес собирает только каркас**: блок `link` несёт путь, базу
  каркас берёт из `FRONTEND_URL`; второй склейки базы в фичах не заводить. Путь
  принимается, только если разобранный адрес остался на origin базы — почему так
  и почему `FRONTEND_URL` не может нести путевой префикс, `docs/decisions.md`
  (03.08.2026).
- Тема и адрес получателя — одна строка без переводов строк; адрес — ещё и
  один-единственный и без display-name: оба уезжают заголовками.
- Французские строки — только из `src/i18n/fr.ts`. Каркас владеет ветками
  `fr.mail.footer` и `fr.mail.senderName`, фичи добавляют свои в тот же объект.

## Транспорт

**За токеном `MAIL_TRANSPORT`**, не ветвлением по окружению: выбор живёт в одном
`useFactory` модуля, тесты подставляют свой транспорт через `overrideProvider`,
не трогая `process.env`.

Контракт транспорта: `send()` либо доставляет, либо бросает `MailDeliveryError` —
**без адреса получателя и тела письма в тексте и стеке**, потому что сервис
пишет их в лог (он же вычищает адрес, если транспорт правило нарушил).

**Локальный режим — умолчание** (`FileMailTransport`): письмо не уходит наружу,
а пишется парой `<время>-<номер>-<тема>.html` и `.txt` в `.mail-outbox` рабочего
каталога (каталог в корневом `.gitignore` — в файлах реальные адреса). Свежий
клон шлёт письма локально без ключа и аккаунта.

**Провайдер — `ScalewayMailTransport`** (Scaleway TEM, HTTP API через нативный
`fetch` с `AbortSignal.timeout`, fetch-функция — в конструкторе, как у
`GeoApiClient`; тесты мокают HTTP без nock/msw). Перевыбору не подлежит; блочная
модель тела и формат outbox — там же, в research. Что держится на нём и правится
только вместе с решением:

- **регион — в URL** (`SCALEWAY_TEM_URL`, `fr-par`), не в конфигурации: обработка
  адресов остаётся в ЕС, и увезти её правкой `.env` нельзя. В конфигурации
  клиента только `secretKey` и `projectId`.
- **Трекинга нет вообще** — ни click, ни open: у провайдера нет такой функции,
  поэтому выключать нечего, а версии тела не могут разойтись переписанной
  ссылкой. Поле с `track` в теле запроса — признак, что провайдера подменили.
- **Успешный ответ проверяется**, а не принимается по статусу: HTTP 200 с
  HTML-страницей отдаёт прокси или captive portal. Почему проверка именно такая
  и почему транспорт ничего не логирует — `docs/decisions.md`, 03.08.2026.
- **Тексты ошибок несут статус и причину, но не тело ответа.** Тело содержит
  адрес получателя в поле `to` — целиком в исключение и в лог оно не попадает
  никогда, включая сообщение упавшего `JSON.parse`. Из ошибочного ответа
  читаются только поля из `REPORTABLE_ERROR_FIELDS` (сейчас одно — `type`,
  код ошибки API) и только если значение выглядит кодом: список ведётся
  перечислением, не «всё, кроме `to`», а формат значения не даёт проехать
  адресу (`docs/decisions.md`, 03.08.2026). Ни того ни другого нет — в отчёте
  остаётся один статус.
- **Тело ошибочного ответа читается не всякое.** Не-JSON не читается вовсе, и
  это отсечка жёсткая — по заголовку `Content-Type`. Размер же сверяется только
  объявленный: `Content-Length` больше 16 КиБ читать нечего, но ответ **без**
  этого заголовка границы по размеру не имеет — читается целиком, каким бы ни
  был. TEM `Content-Length` присылает, а от страницы captive portal или прокси
  защищает первая отсечка; байтовой границы у чтения нет, и обещать её в
  комментариях не надо.
- **Причина недоступности передаётся отдельной причиной (`cause`)** и только
  именем: `fetch` сообщает о таймауте `DOMException`, а `MailService`
  разматывает цепочку причин, пока это `Error`, — иначе в логе останется «не
  достучались» без «почему».
- **Редиректам сказано `error`**: иначе токен и всё письмо повторились бы на том
  хосте, который назван в `Location`, а его ответ прошёл бы как успешный — то
  есть регион в URL перестал бы что-либо гарантировать.

Переменные транспорта объявлены и проверяются на старте (переменная
`MAIL_TRANSPORT` — не путать с одноимённым токеном выше, `MAIL_OUTBOX_DIR`,
`MAIL_SENDER_DOMAIN`, ключи провайдера — `src/config/env.validation.ts`, правила
— `../../CLAUDE.md`), а читает их `useFactory` модуля — один раз при старте и
больше нигде:

- всё, кроме `SENDING_TRANSPORT` (константа `mail-transport-name.ts`, она же
  включает условную валидацию ключей в схеме окружения), — локальный транспорт;
  незаданная переменная тоже. Список имён транспортов живёт здесь же, а не в
  схеме: схема проверяет значение, которое объявляет этот модуль. Значения вне
  списка до фабрики не доходят — их отвергает схема;
- ключи провайдера берутся `getOrThrow`, без подстановки пустой строки:
  приложение с пустым ключом стартует здоровым, а письма отвергает провайдер;
- каталог outbox всегда задан: `.mail-outbox` подставляет схема окружения
  умолчанием `MAIL_OUTBOX_DIR`, поэтому параметр конструктора транспорта
  **обязательный** — транспорт вне Nest обязан назвать каталог сам. Единственное
  написание имени — `DEFAULT_MAIL_OUTBOX_DIR` в `FileMailTransport`, схема его
  импортирует (вне кода их два — `.gitignore` и `.env.example`, правятся вместе
  с умолчанием; `docs/decisions.md`, 03.08.2026).
