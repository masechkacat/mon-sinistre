# CLAUDE.md — `src/communes`

Справочник коммун (импорт COG) и публичный поиск. Правила приложения —
`../../CLAUDE.md`, монорепозитория — корневой. Решения фичи —
`docs/research/commune-referential.md`.

## Импорт справочника (`import/`)

- **`GeoApiClient`** — нативный `fetch` Node 24 с `AbortSignal.timeout(60 с)`,
  fetch-функция передаётся через конструктор (тесты мокают HTTP без nock/msw).
  Каждая запись валидируется на четыре обязательных поля (`code`, `nom`,
  `codeDepartement`, `departement.nom`); ответ короче
  `MIN_EXPECTED_COMMUNES = 30_000` отклоняется — неполные данные роняют импорт,
  а не пропускаются молча.
- **`CommuneImportService`** — обычный класс без Nest-контекста: seed зависит
  только от `DB_*` и сети (при появлении регулярной актуализации оборачивается
  Nest-провайдером через `useFactory`). Upsert по `codeInsee` чанками по 500;
  `update` задаёт `name`/`nameNormalized`/`departement*`/`sourceUrl`/
  `sourceVerifiedAt` (дата запуска, UTC-полночь) и **не трогает**
  `effectiveTo`/`successorCodeInsee`; исчезнувшие из ответа коды никогда не
  удаляются.
- Итоговая сверка: число успешных upsert'ов равно числу записей источника,
  иначе импорт завершается ошибкой. В логах — только счётчики и коды INSEE.
- Запуск — `npm run seed` (`prisma db seed` → ts-node с tsconfig-paths, скрипт
  сам грузит `.env`). Импорт идемпотентен, повторный запуск безопасен.

## Нормализация названий

`normalize-commune-name.ts` — **единственный** способ получить поисковый ключ
названия: lowercase → NFD → удаление `\p{M}` → `œ`→`oe`, `æ`→`ae` → `’`→`'`.
Ею заполняется `Commune.nameNormalized` при импорте и ею же нормализуется `q` в
поисковом запросе; второй реализации быть не должно, иначе запись и чтение
разъедутся.

Апострофы, дефисы и пробелы сохраняются осознанно как разделители («lhay» не
находит «L'Haÿ-les-Roses»), но их типографские варианты приводятся к одному —
`docs/decisions.md` (02.08.2026).

Функция даёт ключ только для названий: ветка поиска по коду INSEE сравнивает
«сырой» `q` с `codeInsee`, который импорт хранит как есть, в верхнем регистре
(`2A004`). Тест — `normalize-commune-name.spec.ts`, без базы.

## Колонка `nameNormalized`

Заведена миграцией `add_commune_name_normalized`: **nullable**, `COLLATE "C"`,
обычный btree `Commune_nameNormalized_idx`.

Байтовый порядок — требование переносимости, не оптимизация: под локальными
collation порядок выдачи меняется между образами Postgres (почему и как
проверено — `docs/decisions.md`, 02.08.2026); под ним же btree обслуживает и
префиксный `LIKE`, и `ORDER BY`, класс оператора `text_pattern_ops` не нужен.
Collation Prisma не выражает — она живёт только в SQL миграции и дрейфом не
считается; сторожит её int-тест, потому что `migrate dev` потерю collation
молча пропустит. Тесты структуры — `commune-name-normalized.int-spec.ts`.

**Порядок развёртывания обязателен: `migration:deploy` → `seed`.** Правило
нормализации в SQL не повторяется: backfill существующих строк — перезапуск
идемпотентного импорта, который колонку заполняет. Пропуск второго шага не
сломает ничего заметно — поиск по названию просто вернёт пустой список на всех
запросах, потому что у строк не будет ключа; для аудитории продукта это худший
вид отказа. Поэтому `commune-search-key.check.ts` на `onApplicationBootstrap`
считает строки без ключа и пишет warning — предупреждает, но не валит
приложение: частично импортированный справочник всё же отвечает по тем
коммунам, что знает. Ужесточение до `NOT NULL` — отдельной миграцией и только
после backfill'а на всех развёртываниях: она сделает пропуск невозможным и
заменит собой эту проверку.

## Поиск `GET /communes?q=`

Публичный: guard'ов по умолчанию в проекте нет, глобальный throttler покрывает
эндпоинт без дополнительной настройки. Префикс названия или точный код INSEE,
только действующие коды, лимит `COMMUNE_SEARCH_LIMIT` из contracts.

- **По названию** — по `nameNormalized`: `q` проходит через
  `normalizeCommuneName`, поэтому «chateau» находит «Château-Thierry».
  Сортировка — по той же колонке, а не по `name` (иначе «Étampes» уехал бы в
  конец выдачи); порядок одинаков везде благодаря `COLLATE "C"`.
- **По коду INSEE** — `q.toUpperCase()` против `codeInsee`: коды хранятся как их
  отдаёт COG, в верхнем регистре, и набранное с телефона «2a004» иначе не нашло
  бы ничего (буквы есть только в корсиканских 2A/2B). Нормализацию к коду
  применять нельзя — она предназначена для названий.
- Нормализованный префикс проходит через `escapeLikePattern` (`src/prisma/`):
  `startsWith` Prisma LIKE-символы не экранирует. Ровно один раз — функция не
  идемпотентна.

Swagger — response-класс, реализующий контракт через `implements`, и
`@ApiOkResponse` на методе; свойства описывает CLI-плагин.
