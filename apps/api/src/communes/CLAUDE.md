# CLAUDE.md — `src/communes`

Справочник коммун (импорт COG) и публичный поиск. Решения фичи —
`docs/research/commune-referential.md`.

## Импорт справочника (`import/`)

- **`GeoApiClient`** — нативный `fetch`, функция передаётся через конструктор
  (тесты мокают HTTP без nock/msw). Ответ короче `MIN_EXPECTED_COMMUNES`
  отклоняется: неполные данные роняют импорт, а не пропускаются молча.
- **`CommuneImportService`** — обычный класс без Nest-контекста: seed зависит
  только от `DB_*` и сети. Upsert по `codeInsee`; `update` **не трогает**
  `effectiveTo`/`successorCodeInsee`, исчезнувшие из ответа коды никогда не
  удаляются.
- Импорт идемпотентен, повторный `npm run seed` безопасен — им же делается
  backfill (см. «Колонка» ниже).

## Нормализация названий

`normalize-commune-name.ts` — **единственный** способ получить поисковый ключ
названия: ею заполняется `Commune.nameNormalized` при импорте и ею же
нормализуется `q` в поиске; второй реализации быть не должно, иначе запись и
чтение разъедутся. Функция даёт ключ только для названий — к кодам INSEE не
применять.

## Колонка `nameNormalized`

Заведена миграцией `add_commune_name_normalized`: **nullable**, `COLLATE "C"`,
обычный btree `Commune_nameNormalized_idx`.

Байтовый порядок — требование переносимости, не оптимизация: под локальными
collation порядок выдачи меняется между образами Postgres. Под ним же btree
обслуживает и префиксный `LIKE`, и `ORDER BY` — класс оператора
`text_pattern_ops` не нужен.
Collation Prisma не выражает — она живёт только в SQL миграции и дрейфом не
считается; сторожит её int-тест, потому что `migrate dev` потерю collation
молча пропустит. Тесты структуры — `commune-name-normalized.int-spec.ts`.

**Порядок развёртывания обязателен: `migration:deploy` → `seed`.** Правило
нормализации в SQL не повторяется: заполняет колонку идемпотентный импорт.
Пропуск второго шага не ломает ничего заметно — поиск по названию просто
вернёт пустой список на всех запросах; для аудитории продукта это худший вид
отказа. Против этого работают два разных механизма, потому что случаи разные:
`nameNormalized` объявлена `NOT NULL`, поэтому строка без ключа невозможна —
неполный импорт валит миграцию; а справочник, не импортированный вовсе, ни
одной строки не нарушает, и о нём предупреждает `commune-referential.check.ts`
на `onApplicationBootstrap` — warning, не отказ: среда, поднятая до первого
импорта, это нормальное промежуточное состояние.

## Поиск `GET /communes?q=`

Публичный: контроллер помечен `@Public()` (`src/auth/public.decorator.ts`) —
иначе глобальный `JwtAuthGuard` (`APP_GUARD`) отвечал бы 401 без токена;
глобальный throttler покрывает эндпоинт без дополнительной настройки. Префикс
названия или точный код INSEE,
только действующие коды, лимит `COMMUNE_SEARCH_LIMIT` из contracts.

- **По названию** — по `nameNormalized`: `q` проходит через
  `normalizeCommuneName`, поэтому «chateau» находит «Château-Thierry».
  Сортировка — по той же колонке, а не по `name` (иначе «Étampes» уехал бы в
  конец выдачи); порядок одинаков везде благодаря `COLLATE "C"`.
- **По коду INSEE** — `q.toUpperCase()` против `codeInsee`: коды хранятся как их
  отдаёт COG, в верхнем регистре, и набранное с телефона «2a004» иначе не нашло
  бы ничего (буквы есть только в корсиканских 2A/2B).
- Нормализованный префикс проходит через `escapeLikePattern` (`src/prisma/`):
  `startsWith` Prisma LIKE-символы не экранирует. Ровно один раз — функция не
  идемпотентна.
