# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Контекст всего монорепозитория — в корневом `../../CLAUDE.md`; он загружен
всегда, и правила оттуда (жёсткие ограничения продукта, доменная модель) здесь
не повторяются. Ниже — только специфика `@mon-sinistre/web`.

## Стек

Next.js 16 (App Router, `src/app/`), React 19, Tailwind CSS 4 (через PostCSS, без tailwind.config). Компонентная база — **shadcn/ui на Base UI**, инициализирована (конфигурация — `components.json`); при добавлении компонентов выбирать Base UI-вариант, не Radix. Отдельных библиотек примитивов сверх этого не подключать. Работа с API — **TanStack Query** (см. «Правила проекта»).

Фундамент клиента (`../../docs/research/web-foundation.md`: тест-инфраструктура,
темы, локализация, слой API) и дизайн-система
(`../../docs/research/design-system.md`) — решения, общие для всех фич: фазы
применяют их, не перевыбирая.

## Команды

Запуск, сборка, линт и тесты — из корня (`npm run dev:web`, `npm run build`, `npm run lint`, `npm run test:web` — Playwright; `npm run test:e2e` — сквозной против реального API и базы, `playwright.e2e.config.ts`). API ожидается на http://localhost:3001. Доменная логика тестируется в API. Линтер — eslint с `eslint-config-next` (flat config в `eslint.config.mjs`).

## Тесты

`tests/` разложен по предмету: `support/` — общие хелперы (`a11y`, `pages`,
`form`, `communes`, `session-mock`, `env`, `strings`, `unsubscribe-api`,
`mock-api`, `deferred`, `sources` — обход `src/**` для правил по исходникам), остальные
каталоги —
спеки по фичам (`auth/`, `veille/`, `home/`, `compte/`, `components/`) и по сквозным
свойствам (`a11y/` — axe, reflow, reduced-motion, i18n, шрифты, контролы; `pages/` — публичные
страницы; `app/` — слой запросов). Новый спек кладётся в существующую группу,
хелпер — только в `support/`, и оттуда же переиспользуется, а не копируется в
соседний спек. Пути к файлам считаются от корня приложения через `__dirname` —
проверять при переносе спека между каталогами.

`e2e/` — сквозные спеки без моков (см. «Команды»); `test:web` их не видит.

## Особенности сборки

- `@mon-sinistre/contracts` резолвится в собранный `dist/` пакета (поле `main`), как и в API: перед первым запуском web нужен `npm run build:contracts` из корня, при параллельной правке типов — `npm run dev:contracts`. `transpilePackages` в `next.config.ts` не меняет резолюцию — он держит пакет в watch-списке dev-сервера, чтобы пересборка dist подхватывалась без перезапуска.
- Включён `typedRoutes` — ссылки на несуществующие маршруты не пройдут типизацию.

## Правила проекта

- **Как выполняется требование доступности** (WCAG 2.1 AA / RGAA 4.1.2 — жёсткое ограничение, корневой `CLAUDE.md`):
  - всё доступно с клавиатуры, видимый фокус не отключается никогда;
  - статус шага передаётся текстом, а не только цветом;
  - поля форм программно связаны с подписями, ошибки объявляются скринридером;
  - динамические изменения объявляются через `role="status"` / `role="alert"`; live-регион монтируется заранее, а меняется только его текст — узел, вставленный в DOM сразу с текстом, скринридеры часто не объявляют;
  - модальные окна: focus trap, `Escape`, возврат фокуса;
  - работоспособность при масштабе 200%, поддержка `prefers-reduced-motion`, обе цветовые темы с контрастом 4.5:1 (3:1 для крупного текста и элементов UI);
  - в layout уже есть skip-link «Aller au contenu principal» на `#contenu` — сохранять этот паттерн на новых страницах.
- **Французский на клиенте**: `<html lang="fr">`. Все пользовательские строки — в типизированном словаре `src/i18n/fr.ts` (импортируется напрямую в серверные и клиентские компоненты, провайдера нет); даты — только через хелперы `src/i18n/date.ts` (вход — `IsoDate`, не `Date`), не `toLocaleDateString` по компонентам. Строку, забытую в JSX или в текстовом атрибуте (`alt`, `aria-label`…), ловит правило `i18next/no-literal-string` в `eslint.config.mjs`. Тексты рассчитаны на пользователя, столкнувшегося с процедурой впервые и в стрессе: административные и страховые термины (arrêté, CatNat, franchise, expertise…) при первом употреблении объясняются простыми словами.
- **Обращения к API — только через TanStack Query** (`@tanstack/react-query`): `useQuery` на чтение, `useMutation` на запись, ключи запросов и функции запроса — в общем слое клиента, не разбросаны по компонентам. Ручной `fetch` в компоненте с `useState`/`useEffect` не заводить: состояния загрузки и ошибки нужны на каждом экране, а французское сообщение об ошибке вместо пустого экрана — требование продукта, и удержать его одинаковым удаётся только в одном месте. Серверные компоненты, которым данные нужны на рендере, читают API напрямую — Query нужен там, где есть состояние на клиенте. Канон — существующий слой `src/lib/api/` (ниже): новый запрос повторяет форму `account.ts`/`veille.ts`. Скилл **tanstack-query** — справочник по API библиотеки (SSR-гидрация, инвалидация, `select`), к нему обращаются с конкретным вопросом, не перед каждым хуком.
  Слой — `src/lib/api/`: `config.ts` (базовый адрес из `NEXT_PUBLIC_API_URL`), `client.ts` (fetch-обёртки `apiFetch` для публичных эндпоинтов и `authApiFetch` для сессионных, `ApiError`), `keys.ts` (фабрика ключей запросов), `session.ts` (access-токен в памяти модуля, тихий refresh, выход, подписка на токен), `use-session-guard.ts` (защита клиентской страницы), `use-session.ts` (состояние сессии для тех, кто её только показывает), `account.ts`/`veille.ts`/`reminders.ts` (запросы своих фич). Все запросы уходят с `credentials: 'include'`: `refresh_token` — httpOnly-кука с другого origin, без этого браузер не примет её при входе и не удалит при выходе. Различение публичного и сессионного вызова — по эндпоинту, а не по наличию токена в памяти: 401 публичной формы принадлежит самой форме, и подменять его редиректом на вход нельзя. Провайдер — `src/app/providers.tsx` (`QueryClient` в `useState`, там же общие `defaultOptions` — ретраи не задавать по месту), подключён в `layout.tsx` вокруг всей обвязки. Route handler зовёт тот же слой, но экрана с `RequestError` у него нет: он ловит сбой сам, отвечает кодом и пишет причину в `console.error` — единственное место в клиенте, где логирование уместно. Обработчики ссылки отписки из письма своего `route.ts` не пишут — его собирает `oneClickUnsubscribeHandlers` (`src/lib/one-click-unsubscribe.ts`) по эндпоинту и странице подтверждения рассылки, а сам экран с кнопкой — `TokenConfirmScreen` (`src/components/token-confirm-screen.tsx`).
- Отображаемые подписи к enum-значениям (статусы синистра и шагов) живут в локализации клиента; сами значения и пороги — из `@mon-sinistre/contracts`.
- **Любое изменение UI завершено только после `/ui-review`.** «Код написан и компилируется» — не завершение.
- Расчётные даты всегда подаются как ориентировочные, со ссылкой на источник (`SourceReference`) и предложением сверить с договором страхования и страховщиком — приложение не даёт юридических консультаций.
