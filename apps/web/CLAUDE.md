# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Контекст всего монорепозитория — в корневом `../../CLAUDE.md`. Здесь — специфика `@mon-sinistre/web`.

## Стек

Next.js 16 (App Router, `src/app/`), React 19, Tailwind CSS 4 (через PostCSS, без tailwind.config). Компонентная база — **shadcn/ui на Base UI** (дефолт shadcn с июля 2026; при инициализации выбирать Base UI, не Radix). Отдельных библиотек примитивов сверх этого не подключать. Работа с API — **TanStack Query** (см. «Правила проекта»).

## Команды (из apps/web)

```bash
npm run dev    # http://localhost:3000
npm run build
npm run lint
```

API ожидается на http://localhost:3001. Тестов в этом пакете нет — доменная логика тестируется в API. Линтер — eslint c `eslint-config-next` (flat config в `eslint.config.mjs`), запускается pre-commit хуком.

## Особенности сборки

- `@mon-sinistre/contracts` резолвится в собранный `dist/` пакета (поле `main`), как и в API: перед первым запуском web нужен `npm run build:contracts` из корня, при параллельной правке типов — `npm run dev:contracts`. `transpilePackages` в `next.config.ts` не меняет резолюцию — он держит пакет в watch-списке dev-сервера, чтобы пересборка dist подхватывалась без перезапуска.
- Включён `typedRoutes` — ссылки на несуществующие маршруты не пройдут типизацию.

## Актуализация документации

При изменении архитектуры клиента обновлять этот файл в том же коммите: инициализация shadcn/ui на Base UI (запланирована, но ещё не выполнена), появление слоя работы с API, механизма локализации, тестов. Изменения, затрагивающие весь монорепозиторий, — в корневом `../../CLAUDE.md`.

## Правила проекта

- **Язык интерфейса — французский** (`<html lang="fr">`). Все пользовательские строки — в файлах локализации, не в компонентах; даты форматируются по локали `fr-FR`. Тексты рассчитаны на пользователя, столкнувшегося с процедурой впервые и в стрессе: административные и страховые термины (arrêté, CatNat, franchise, expertise…) при первом употреблении объясняются простыми словами.
- **Доступность — обязательное требование** (раздел 7 ТЗ, ориентир WCAG 2.1 AA / RGAA 4.1.2). Ключевое:
  - всё доступно с клавиатуры, видимый фокус не отключается никогда;
  - статус шага передаётся текстом, а не только цветом;
  - поля форм программно связаны с подписями, ошибки объявляются скринридером;
  - динамические изменения объявляются через `role="status"` / `role="alert"`;
  - модальные окна: focus trap, `Escape`, возврат фокуса;
  - работоспособность при масштабе 200%, поддержка `prefers-reduced-motion`, обе цветовые темы с контрастом 4.5:1 (3:1 для крупного текста и элементов UI).
  - В layout уже есть skip-link «Aller au contenu principal» на `#contenu` — сохранять этот паттерн на новых страницах.
- **Обращения к API — только через TanStack Query** (`@tanstack/react-query`): `useQuery` на чтение, `useMutation` на запись, ключи запросов и функции запроса — в общем слое клиента, не разбросаны по компонентам. Ручной `fetch` в компоненте с `useState`/`useEffect` не заводить: состояния загрузки и ошибки нужны на каждом экране, а французское сообщение об ошибке вместо пустого экрана — требование продукта, и удержать его одинаковым удаётся только в одном месте. Серверные компоненты, которым данные нужны на рендере, читают API напрямую — Query нужен там, где есть состояние на клиенте. Перед написанием кода на Query вызывать скилл **tanstack-query** (актуальный API v5, паттерны ключей, инвалидации и SSR-гидрации).
- Статусы синистра и шагов, константы порогов — из `@mon-sinistre/contracts`; отображаемые подписи к enum-значениям живут в локализации клиента, в contracts их нет.
- **Любое изменение UI завершено только после визуальной проверки.** Обязательно: (1) запустить приложение и проверить изменение вживую в браузере (Playwright MCP: снапшот/скриншот затронутых страниц, взаимодействие с изменёнными элементами); (2) прогнать проверку через скилл **ui-ux-pro-max** (дизайн-ревью изменённого UI). Пока оба пункта не выполнены, задача не считается завершённой — «код написан и компилируется» недостаточно.
- Расчётные даты всегда подаются как ориентировочные, со ссылкой на источник (SourceReference) и предложением сверить с договором страхования и страховщиком — приложение не даёт юридических консультаций.
