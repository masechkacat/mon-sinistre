# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

Jalons — веб-приложение для сопровождения цикла продления прав MDPH (французская комиссия по делам инвалидности). Пользователь вводит дату истечения текущих прав, приложение разворачивает из справочника процедур персональный план подготовки, следит за сроками годности документов и рассылает напоминания. Оно не даёт юридических консультаций и не подаёт документы — его задача не дать пропустить сроки.

Полное техническое задание: `docs/technical-specification.md`. Оно определяет функциональные требования, но не контракты API и не структуру модулей — эти решения принимаются в коде.

## Структура монорепозитория

npm workspaces, три пакета:

- `packages/contracts` (`@jalons/contracts`) — типы, enum'ы и константы, общие для API и клиента. Собирается **первым**: API импортирует его из `dist/`.
- `apps/api` (`@jalons/api`) — NestJS + Fastify + TypeORM + PostgreSQL, порт 3001.
- `apps/web` (`@jalons/web`) — Next.js (App Router) + Tailwind 4, порт 3000. Использует contracts напрямую из исходников через `transpilePackages`.

У каждого приложения есть свой CLAUDE.md с деталями.

## Команды (из корня)

```bash
npm run db:up            # PostgreSQL 17 в Docker (нужен apps/api/.env)
npm run build:contracts  # обязательно перед первым запуском API
npm run dev:api          # NestJS в watch-режиме, http://localhost:3001, /docs — OpenAPI
npm run dev:web          # Next.js, http://localhost:3000
npm run dev:contracts    # tsc --watch для contracts (при параллельной правке типов)
npm run build            # contracts → api → web
npm test                 # jest в apps/api (тесты есть только там)
npm run lint             # eslint по всем workspace'ам
```

Один тест: `npm test --workspace @jalons/api -- health.controller` (jest ищет `*.spec.ts` по подстроке пути).

Окружение: Node.js ≥ 24, Docker. Секреты — `cp apps/api/.env.example apps/api/.env`, значения генерируются `openssl rand -base64 48`.

## Архитектура и доменная модель

Ключевые понятия зафиксированы в `packages/contracts/src/`:

- **Bénéficiaire** (подопечный) → **Dossier** (один цикл продления: `PREPARATION → DEPOSE → DECISION_RECUE → ARCHIVE`) → **Steps** (шаги плана) + **DocumentRecords** (записи о документах, без файлов).
- **План разворачивается из одной даты** — даты истечения прав. Дата подачи = истечение минус срок рассмотрения; даты шагов = опорная точка (`DATE_EXPIRATION` или `DATE_DEPOT`) плюс смещение в днях.
- **Приоритет источников срока рассмотрения**: значение пользователя → значение департамента → значение процедуры по умолчанию (`ReviewDurationSource`). Источник всегда показывается пользователю.
- **Статусы шагов вычисляются на чтении**, в базе хранятся только `FAIT` и `NON_APPLICABLE`. Пороги (`SOON_THRESHOLD_DAYS = 30`, интервалы напоминаний 30/14/3 дня) — константы в contracts.
- Досье хранит **копию плана** на момент создания: изменение шаблона процедуры не трогает существующие досье. Шаги, добавленные пользователем (`fromTemplate: false`), никогда не пересчитываются.
- Все доменные даты — `IsoDate` (строка `YYYY-MM-DD`, без времени и таймзон). Не заменять на `Date`.

## Жёсткие ограничения (из ТЗ, нарушать нельзя)

- **Никаких медицинских данных в базе**: ни диагнозов, ни содержимого заключений — только тип документа, даты и факт наличия (§ 11). Это осознанное решение, выводящее проект из-под требований к хостингу медицинских данных.
- **Доступность — WCAG 2.1 AA / RGAA 4.1.2** (§ 9 ТЗ) — обязательное требование наравне с функциональными; аудитория — люди с инвалидностью и их семьи.
- Проверка принадлежности объектов пользователю выполняется **в запросе к базе**, а не после выборки; ответ на чужой объект не раскрывает факт его существования.
- Язык интерфейса — **французский**; все пользовательские строки — в файлах локализации, contracts не содержит текстов для UI.
- Изменения схемы БД — только через миграции; `synchronize` в продакшене запрещён.
- В логи не попадают имена подопечных, email и комментарии к документам.
- Справочные данные всегда несут ссылку на источник и дату сверки (`SourceReference`); при расхождении сведений применяется более консервативное значение.

## Актуализация документации

При изменении архитектуры обновлять документацию в том же коммите, что и код:

- новый пакет в workspace, изменение порядка сборки или команд — этот файл и README.md;
- изменения внутри `apps/api` или `apps/web` (новые модули, изменение состояния скелета, новые правила) — CLAUDE.md соответствующего приложения;
- отступление от ТЗ или уточнение требований — зафиксировать решение и его причину (в `docs/`), само ТЗ не редактировать молча.

Устаревшая инструкция хуже отсутствующей: следующая сессия будет ей доверять.

## Тестирование

Обязательное покрытие — логика расчёта дат: развёртывание плана, приоритет сроков рассмотрения, пересчёт при изменении даты подачи, вычисление статусов шагов, проблемные документы, поводы для напоминаний (раздел «Тестирование» ТЗ). Граничные случаи: конец месяца, високосный год, смещение в прошлое, дата подачи в прошлом.
