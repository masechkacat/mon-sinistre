# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Главное правило: не дублировать

Ни код, ни текст. Один факт живёт в одном месте, одна логика — в одной функции.

Поэтому:

- **Прежде чем писать — поискать.** Если такое правило, функция или объяснение
  уже есть, дописывать второе не надо: сослаться на первое или поправить его.
- **Ссылка вместо копии.** `CLAUDE.md` вложены (корневой загружен всегда), и
  родитель на правило модуля даёт строку «что и где», а не пересказ.
- **Комментарий — только там, где код выглядит ошибкой, но ошибкой не является**
  (`escapeLikePattern` не идемпотентна; редирект запрещён, иначе токен уедет на
  чужой хост). Что делает код — видно из кода, зачем — из тестов, а стухший
  комментарий врёт следующей сессии. Ход обсуждения и «почему я выбрал такой
  вариант» в код не попадают: для этого есть git.
- **Добавляешь абзац — посмотри, какой удалить.** Коммит, который только
  дописывает прозу, почти всегда лишний.
- **Документация правится в том же коммите, что и код**, по «Карте документации»
  ниже: устаревшая инструкция хуже отсутствующей — следующая сессия будет ей
  доверять.

## О проекте

**Mon Sinistre** — assistant catastrophe naturelle: уведомляет жителей выбранных коммун в день публикации arrêté в Journal Officiel и ведёт пострадавшего через страховой случай — план действий с первого дня после события, 30-дневный срок декларации, сроки страховщика, инвентарь ущерба с фото. Оно не даёт юридических консультаций и не взаимодействует со страховщиком от имени пользователя — его задача не дать пропустить сроки.

## Структура монорепозитория

npm workspaces, три пакета:

- `packages/contracts` (`@mon-sinistre/contracts`) — типы, enum'ы и константы, общие для API и клиента. Собирается **первым**: API импортирует его из `dist/`.
- `apps/api` (`@mon-sinistre/api`) — NestJS + Fastify + Prisma + PostgreSQL.
- `apps/web` (`@mon-sinistre/web`) — Next.js (App Router) + Tailwind 4. Contracts резолвится в его `dist/` (поле `main`), поэтому web тоже требует собранный contracts; `transpilePackages` нужен, чтобы dev-сервер подхватывал пересборку пакета.

## Команды и проверки

Команды — скрипты корневого `package.json`. Что из них не выводится:

- `.claude/` не входит в workspaces, eslint и jest его **не видят** — для его
  скриптов есть отдельный `npm run test:tooling` (встроенный `node --test`,
  новый `.claude/*.test.js` подхватывается сам).
- Pre-commit хук (`.githooks/`, подключается скриптом `prepare`) гоняет lint,
  test и test:tooling и **не должен изменять файлы**: `lint` без `--fix`,
  автопочинка — отдельным `lint:fix` в API.

## Ralph Loop — автономный прогон фазы

`node .claude/ralph.js` (`--dry-run` — проверить обвязку, не запуская агента).
Всё о цикле — правила итерации, предполётные проверки, условия останова,
`allowedTools` — `.claude/ralph.md` и `.claude/ralph.js`.

## Коммиты и PR

Живой номер после ключевого слова (`Closes`, `Fixes`, `Resolves` и формы) —
**ровно один** на коммит: GitHub ищет эти слова по всему тексту коммита и PR, не
разбирая оформления, и закрывает названный issue. Поэтому примеры — только с
плейсхолдером (`Closes #<N>`), а описывая инцидент — «issue 12», не трейлер.

## Архитектура и доменная модель

Сущности и их отношения — ТЗ § 4; реляционная схема — `docs/research/data-model.md`
(связи, ключи, каскады, версионирование справочников, идемпотентность рассылок,
RGPD-удаление). Prisma-модели и миграции обязаны следовать модели; отступление —
правкой самой модели, не молча.

Правила, которые из ТЗ не выводятся и живут в коде:

- **План разворачивается от опорных дат** (`StepAnchor`). Шаг с ещё не
  наступившим якорем существует без `plannedDate` и получает дату, когда якорь
  появляется — так синистр, созданный до публикации arrêté, автоматически
  получает 30-дневный дедлайн в момент, когда монитор находит arrêté.
- **Статусы шагов вычисляются на чтении**, в базе хранятся только `FAIT` и
  `NON_APPLICABLE`. Пороги (`SOON_THRESHOLD_DAYS = 30`, напоминания 30/14/3,
  усиленная шкала дедлайна декларации 21/14/7/3/1) — константы contracts, не
  дублировать в приложениях.
- Синистр хранит **копию плана** на момент создания: изменение шаблона не
  трогает существующие синистры. Шаги, добавленные пользователем
  (`fromTemplate: false`), никогда не пересчитываются.
- Все доменные даты — `IsoDate` (брендированная строка `YYYY-MM-DD`, без времени
  и таймзон; произвольный `string` не пройдёт типизацию — конструировать через
  `toIsoDate`/`isIsoDate` из contracts). Не заменять на `Date`.

## Жёсткие ограничения (из ТЗ, нарушать нельзя)

Осознанный кеш ТЗ § 7 для контекста сессий: правится вслед за ТЗ, не вместо
него. В `CLAUDE.md` приложений и модулей эти пункты **не повторяются** — этот
файл загружен всегда.

- **Доступность — WCAG 2.1 AA / RGAA 4.1.2** (§ 7 ТЗ) — обязательное требование наравне с функциональными: аудитория — люди в остром стрессе после катастрофы, значительная доля пожилых. Публикуемая déclaration d'accessibilité — часть продукта.
- **Файлы пользователей приватны**: фото и justificatifs — только по коротким подписанным URL, публичных бакетов нет.
- Проверка принадлежности объектов пользователю выполняется **в запросе к базе**, а не после выборки; ответ на чужой объект не раскрывает факт его существования.
- Язык интерфейса — **французский**; все пользовательские строки — в файлах локализации, contracts не содержит текстов для UI.
- Изменения схемы БД — только через `prisma migrate`; `prisma db push` в продакшене запрещён.
- В логи не попадают email, адреса, содержимое инвентаря и файлы.
- Email наблюдателей (Veille): double opt-in, отписка в один клик, немедленное удаление по запросу (RGPD).
- **Юридические сроки — только из справочника `DeadlineRule`** с `SourceReference`; захардкоженных юридических цифр в коде нет.
- **Дата публикации arrêté — только из XML JORF**; дата появления файла в выгрузке DILA и даты из GASPAR источниками не являются (GASPAR ошибается, проверено 30.07.2026).
- Справочные данные всегда несут ссылку на источник и дату сверки (`SourceReference`); при расхождении сведений применяется более консервативное значение; при расхождении GASPAR и JORF приоритет у JORF.

## Тестирование

Обязательное покрытие задаёт **ТЗ § 9** — состав не сокращать: парсер arrêté на
фикстурах реальных XML из JORF, вычисление дедлайнов, статусы шагов и шаги без
`plannedDate`, поводы для напоминаний и их идемпотентность, дедупликация NOR,
переходы статуса при отказе. Обязательные краевые случаи каждого пункта
перечислены там же.
