## Фаза 1: Prisma + модель Commune + публичный поиск (Tracer Bullet)

**Цель:** работающий публичный эндпоинт поиска коммун поверх реальной базы —
первый сквозной путь через Prisma в проекте. Поиск пока по точному префиксу
(без нормализации диакритики — она в фазе 3), но уже с limit, сортировкой,
фильтром действующих кодов и département в ответе.
**Затрагивает:** contracts / api / db

**Задачи:**

- [ ] Тесты (до кода): поиск по началу названия, по точному действующему коду
      INSEE (ровно одна коммуна; включая корсиканский код вида `2A004` — коды
      не только цифровые), поиск по коду с заполненным `effectiveTo` возвращает
      пусто, limit 10 и сортировка по названию (тестовые данные — без
      диакритики в первой букве: до фазы 3 сортировка идёт по `name` и зависит
      от collation базы), исключение записей с заполненным `effectiveTo` из
      поиска по названию, ответ содержит название и département, эндпоинт
      доступен без аутентификации, пустой или слишком короткий `q` отклоняется
      валидацией (минимальная длина — 2 символа).
- [ ] Настроить инфраструктуру интеграционных тестов по решению из
      research-отчёта: отдельная тестовая база `${DB_NAME}_test` на
      docker-compose Postgres, конфиг `jest.int.config.js` (`*.int-spec.ts`,
      `maxWorkers: 1`), globalSetup с `CREATE DATABASE` и
      `prisma migrate deploy`, `TRUNCATE` между тестами; зафиксировать в
      `apps/api/CLAUDE.md`.
- [ ] Подключить Prisma 7 строго по `apps/api/CLAUDE.md` («Текущее состояние»):
      `prisma.config.ts` (url из `DB_*`), `schema.prisma` с генератором
      `prisma-client` и явным `output`, адаптер `@prisma/adapter-pg`,
      `PrismaModule`/`PrismaService` с disconnect в `onModuleDestroy`.
- [ ] Модель `Commune` по `docs/research/data-model.md` § 3 (codeInsee PK, name,
      departementCode, departementName, effectiveTo, successorCodeInsee →
      Commune, sourceUrl, sourceVerifiedAt) + первая миграция `prisma migrate`.
- [ ] `CommunesModule`: `GET /communes?q=` — префикс по названию или точный код
      INSEE, только действующие коды (`effectiveTo IS NULL`), limit и порядок
      из задач выше; DTO запроса с class-validator (глобальный whitelist,
      `q` — строка от 2 символов, без формата «только цифры»: коды Корсики
      содержат буквы).
- [ ] Константа `COMMUNE_SEARCH_LIMIT = 10` в `packages/contracts` (собрать
      `npm run build:contracts`); обновить `apps/api/CLAUDE.md` — Prisma
      подключена, раздел «Текущее состояние» переписать в том же коммите.

**Когда готова:** e2e/интеграционный тест: при двух записях в базе
`GET /communes?q=Châ` без токена возвращает коммуну с названием и département;
`GET /communes?q=02168` возвращает ровно одну.

## Фаза 2: Импорт COG из geo.api.gouv.fr

**Цель:** база заполнена всеми коммунами актуального COG, импорт можно
безопасно перезапускать; каждая запись несёт источник и дату сверки.
**Затрагивает:** api / db

**Задачи:**

- [ ] Тесты (до кода, HTTP замокан): повторный импорт не создаёт дублей;
      изменившееся название обновляется на месте при том же коде; код,
      исчезнувший из ответа источника, остаётся в базе без изменений;
      расхождение числа записей (усечённый ответ или потеря при вставке) —
      ошибка импорта, не тихий пропуск; запись без любого из обязательных
      полей (`code`, `nom`, `codeDepartement`, `departement.nom`) — ошибка
      импорта, не пропуск записи; ответ короче `MIN_EXPECTED_COMMUNES` —
      ошибка импорта.
- [ ] Клиент geo.api.gouv.fr по решению из research-отчёта: `GET /communes`
      c `fields=code,nom,codeDepartement,departement` (название département
      приходит вложенным объектом, отдельный запрос к `/departements` не
      нужен), нативный `fetch` с `AbortSignal.timeout`, fetch-функция через
      конструктор для моков; ответ — один JSON-массив без пагинации, контроль
      полноты — валидация четырёх полей каждой записи + нижний порог
      `MIN_EXPECTED_COMMUNES = 30_000`.
- [ ] Импорт-сервис: upsert по `codeInsee` (обновляет `name`, никогда не
      удаляет отсутствующие в ответе коды), каждой записи — `sourceUrl` и
      `sourceVerifiedAt` (дата запуска импорта).
- [ ] Итоговая сверка: число записей, обработанных импортом (upsert'ов), равно
      числу коммун, полученных от источника, иначе импорт завершается ошибкой
      с логом (без email/персональных данных — тут их и нет). Сравнивать
      именно обработанные записи, а не все действующие строки в базе: коды,
      исчезнувшие из ответа источника, остаются в базе и не должны ронять
      сверку.
- [ ] Запуск разового импорта через `npm run seed` (seed-команда в
      `prisma.config.ts`, как предусмотрено `apps/api/CLAUDE.md`); обновить
      `apps/api/CLAUDE.md` (клиент geo.api, импорт-сервис, seed) в том же
      коммите.

**Когда готова:** после `npm run seed` на пустой базе число записей равно числу
коммун от geo.api.gouv.fr (~35 000); повторный `npm run seed` не меняет число
записей; тесты идемпотентности зелёные.

## Фаза 3: Поиск без учёта регистра и диакритики

**Цель:** «chateau» находит «Château-Thierry» — поиск работает так, как ищут
люди; одноимённые коммуны различимы по département.
**Затрагивает:** api / db

**Задачи:**

- [ ] Тесты (до кода): «chateau» → «Château-Thierry»; «CHATEAU» и «châTEAU» —
      тот же результат; одноимённые коммуны обе в выдаче и различимы по
      département; поиск по коду INSEE и фильтр `effectiveTo` не сломаны.
- [ ] Механизм — по решению из research-отчёта: колонка `nameNormalized`,
      заполняемая при импорте TS-функцией `normalizeCommuneName` (lowercase +
      NFD без диакритики + `œ`→`oe`, `æ`→`ae`); та же функция нормализует `q`
      в запросе. Функция покрывается юнит-тестом без базы.
- [ ] Миграция `prisma migrate`: колонка `nameNormalized` (nullable) + индекс
      `text_pattern_ops` ручным SQL в файле миграции; backfill — перезапуском
      идемпотентного импорта, затем ужесточение до NOT NULL отдельной
      миграцией (по research-отчёту).
- [ ] Обновить импорт (фаза 2) и поисковый запрос `CommunesModule` на
      `nameNormalized` (и в `where`, и в `orderBy` — заодно уходит зависимость
      сортировки от collation); отразить механизм нормализации в
      `apps/api/CLAUDE.md` в том же коммите.

**Когда готова:** тест «`q=chateau` возвращает „Château-Thierry“» зелёный на
данных реального импорта; все критерии готовности PRD закрыты.
