# Plan: Фундамент клиента и главная страница

**PRD**: docs/prd/web-foundation.md
**Research**: docs/research/web-foundation.md. Задачи с пометкой «по
research-отчёту» применяют его решения, а не перевыбирают их.
**Дата**: 2026-08-04
**Статус**: выполнен (15.08.2026). План — снимок на момент планирования и
ретроактивно не правится.

Фича целиком клиентская: все фазы затрагивают только `apps/web`.
`packages/contracts` не меняется (текстов UI в нём не бывает), `apps/api` и
схема БД не затрагиваются. Правила доступности и визуальной проверки UI не
пересказываются в задачах — они в `apps/web/CLAUDE.md` и обязательны для каждой
фазы с UI.

## Новые зависимости ставит владелец до фазы

Ralph Loop зависимости не ставит (`npm install`, `npx` и правка `package.json`
не входят в `allowedTools` — `.claude/ralph.config.json`), а этой фиче они
понадобятся: инициализация shadcn/ui, механизм локализации, инструмент
axe-проверки. Research-отчёт обязан перечислить точный список пакетов и команд
инициализации по каждой фазе; владелец выполняет их вручную **до** запуска
фазы, как это принято в плане emails (раздел «Ограничение research: без новых
зависимостей»).

## Тесты не выделены в отдельную задачу

Проверки названы внутри той задачи, поведение которой подтверждают. Почему
иначе нельзя — docs/plan/emails.md, раздел «Тесты не выделены в отдельную
задачу». Особенность этой фичи: проверок в `apps/web` пока нет вообще
(`apps/web/CLAUDE.md`), поэтому их инфраструктура — не побочный вопрос, а
содержимое скоупа PRD («проверка доступности как часть процесса») и первая
задача фазы 1.

## Фаза 1: Инфраструктура проверок, компонентная база и локализация (Tracer Bullet)

**Цель:** существующая страница-заглушка рендерится через новую компонентную
базу в обеих цветовых темах, все её строки берутся из французских файлов
локализации, и это подтверждается автоматической axe-проверкой, встроенной в
процесс. Это сквозной путь через все слои фундамента; последующие фазы только
добавляют страницы.
**Затрагивает:** web

**Задачи:**

- [ ] Инфраструктура автоматической проверки доступности по research-отчёту:
      axe на каждой странице приложения в обеих темах, в реальном браузере
      (контраст иначе не проверяется); способ запуска и место в конвейере
      (отдельная корневая команда или pre-commit — с учётом того, что браузерный
      прогон медленный, а хук не должен изменять файлы) — по research-отчёту.
      Отразить команду в корневом `package.json` и снять фразу «тестов в этом
      пакете нет» в `apps/web/CLAUDE.md` тем же коммитом. **Проверяется тестами
      (до кода):** прогон зелёный на текущей странице-заглушке и падает на
      намеренно подсунутом нарушении (смоук самой проверки — страница с
      картинкой без `alt` в тестовой обвязке).
- [ ] Инициализация shadcn/ui на Base UI и токены светлой и тёмной тем;
      глобальное отключение анимаций при `prefers-reduced-motion`; способ выбора
      темы — по research-отчёту (если это переключатель — он доступен с
      клавиатуры и объявляет состояние). Обновить `apps/web/CLAUDE.md` тем же
      коммитом (инициализация числится там как запланированная). **Проверяется
      тестами (до кода):** axe-прогон фазы включает правила контраста и зелёный
      в обеих темах; при эмуляции `prefers-reduced-motion` анимации и переходы
      отключены.
- [ ] Механизм локализации по research-отчёту: все пользовательские строки
      существующих layout и страницы — во французских файлах локализации;
      форматирование дат по локали `fr-FR` — единая утилита механизма, не
      `toLocaleDateString` по компонентам. Автоматический контроль «ни одной
      французской строки в компонентах» — способ по research-отчёту (например,
      запрет строковых литералов в JSX линтером с точечными исключениями).
      **Проверяется тестами (до кода):** отрендеренная страница показывает
      строки из файла локализации; контроль литералов падает на нарочно
      оставленной французской строке в компоненте (смоук) и зелёный на
      существующем коде.
- [ ] Каркас страницы: шапка с названием сервиса — ссылкой на главную, подвал
      (ссылки на юридические страницы добавит фаза 4), семантические landmarks
      (`header`/`main`/`footer`), существующий skip-link сохраняется.
      **Проверяется тестами (до кода):** axe-прогон подтверждает landmarks и
      порядок заголовков; проход с клавиатуры — первый `Tab` попадает на
      skip-link, фокус виден на каждом интерактивном элементе.

**Когда готова:** axe-прогон зелёный на странице-заглушке в обеих темах и
встроен в конвейер проверок; страница полностью проходима с клавиатуры с
видимым фокусом; все строки — из файлов локализации, контроль литералов
работает; анимации отключаются при `prefers-reduced-motion`.

## Фаза 2: Главная страница

**Цель:** житель, впервые попавший на сайт, за один экран понимает, что такое
arrêté CatNat, что делает сервис, чего он не делает и что произойдёт дальше.
**Затрагивает:** web

**Задачи:**

- [ ] Тексты главной во французских файлах локализации: что такое catastrophe
      naturelle и arrêté простыми словами (термины объясняются при первом
      употреблении — правило `apps/web/CLAUDE.md`), что делает сервис, чего не
      делает (не даёт юридических консультаций, не общается со страховщиком от
      имени пользователя), что произойдёт дальше. Вычитка текста владельцем —
      на ревью PR. **Проверяется тестами (до кода):** контроль литералов из
      фазы 1 зелёный — тексты только в локализации.
- [ ] Вёрстка главной на компонентной базе: осмысленная структура заголовков
      (один `h1`, без пропуска уровней), при масштабе 200 % и на ширине 320 px
      нет горизонтальной прокрутки. **Проверяется тестами (до кода):**
      axe-прогон зелёный в обеих темах; проверка в браузере на вьюпорте 320 px
      и при масштабе 200 % утверждает отсутствие горизонтальной прокрутки
      (`scrollWidth` не превышает ширину вьюпорта).

**Когда готова:** оба критерия задач зелёные; страница пройдена с клавиатуры;
визуальная проверка в браузере и дизайн-ревью ui-ux-pro-max выполнены (правило
`apps/web/CLAUDE.md`); владелец вычитал тексты на ревью PR.

## Фаза 3: Страницы «не найдено» и «ошибка сервера»

**Цель:** несуществующий адрес и ошибка рендера показывают французские
страницы каркаса, а не системные страницы фреймворка.
**Затрагивает:** web

**Задачи:**

- [ ] Страница «не найдено» (`not-found`): французский текст из локализации,
      ссылка на главную, каркас и темы фазы 1. **Проверяется тестами (до
      кода):** открытие несуществующего адреса показывает французскую страницу
      «не найдено», а не системную страницу Next.js; axe-прогон зелёный в обеих
      темах.
- [ ] Страница «ошибка сервера» (`error` / `global-error`): французский текст
      из локализации; способ спровоцировать ошибку в проверке (тестовый маршрут
      или инъекция ошибки) — по research-отчёту. **Проверяется тестами (до
      кода):** спровоцированная ошибка рендера показывает французскую страницу
      ошибки; axe-прогон зелёный в обеих темах.

**Когда готова:** оба сценария показывают французские страницы, axe зелёный,
страницы проходимы с клавиатуры; визуальная проверка и дизайн-ревью выполнены.

## Фаза 4: Юридические страницы

**Цель:** mentions légales и politique de confidentialité опубликованы и
доступны из подвала каждой страницы — юридическое предусловие сбора любых
данных (форма veille без них не выкатывается).
**Затрагивает:** web

**Задачи:**

- [ ] Черновики текстов mentions légales и politique de confidentialité по
      типовой структуре таких страниц во Франции (структуру фиксирует
      research-отчёт); тексты — во французских файлах локализации; вычитка
      владельцем продукта — на ревью PR. **Проверяется тестами (до кода):**
      контроль литералов зелёный.
- [ ] Страницы на каркасе фазы 1 и работающие ссылки на них в подвале.
      **Проверяется тестами (до кода):** переход по каждой ссылке подвала
      открывает соответствующую страницу; axe-прогон обеих страниц зелёный в
      обеих темах; на 320 px и при 200 % нет горизонтальной прокрутки.

**Когда готова:** обе страницы открываются по ссылкам из подвала, axe зелёный,
проходимы с клавиатуры; владелец вычитал тексты на ревью PR; визуальная
проверка и дизайн-ревью выполнены.

## Фаза 5: Слой обращения к API

**Цель:** у клиента есть единый способ обращения к API — базовый адрес в одном
месте, TanStack Query подключён, ошибка запроса показывается пользователю
по-французски одним общим паттерном. Страницы этой фичи запросов не делают,
поэтому полная проверка слоя — первый реальный запрос формы veille (критерий
её PRD); здесь слой создаётся и проверяется в изоляции.
**Затрагивает:** web

**Задачи:**

- [ ] Слой клиента по правилам `apps/web/CLAUDE.md` (перед кодом — скилл
      tanstack-query): `QueryClientProvider` в layout, базовый адрес API из
      конфигурации окружения в одном месте, общее место для ключей и функций
      запросов. **Проверяется тестами (до кода):** приложение рендерится с
      подключённым провайдером; базовый адрес читается из окружения, второго
      литерала адреса в коде нет.
- [ ] Единый показ ошибки запроса: общий компонент/паттерн с французским
      сообщением из локализации, объявляемый скринридеру (`role="alert"` —
      правило `apps/web/CLAUDE.md`). **Проверяется тестами (до кода):** запрос
      к недоступному API (мок) приводит к показу французского сообщения из
      локализации, а не пустого экрана; axe-прогон состояния с ошибкой зелёный.

**Когда готова:** оба теста зелёные; слой готов к использованию фичей veille —
её PRD владеет критерием «слой проверен на первом реальном запросе».
