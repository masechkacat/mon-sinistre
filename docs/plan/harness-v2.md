# Plan: Харнес v2 — петли вместо абзацев

**Research**: docs/research/harness-v2.md (13.10.2026) — решения приняты
там, фазы ниже их применяют.
**Дата**: 2026-10-13

Фазы выполняются в сессии с человеком, не Ralph: они правят сам цикл.
Каждая — один PR; порядок важен: без фазы 0 остальные не измеримы, без
фазы 1 фаза 2 правит очередь, которую через неделю снова сгенерируют
вперёд.

**Когда весь план готов:** одна продуктовая фаза под новым харнесом даёт
правки ревью не более чем в трети PR, итерацию дешевле базы на четверть,
прирост тестов не быстрее прироста кода.

**Затрагивает:** `.claude/ralph.js`, `.claude/metrics.js`, корневой `CLAUDE.md`

- [x] Research и план этой фичи.

**Когда готова:** `npm run test:tooling` зелёный; `node .claude/metrics.js

**Цель:** решение доезжает до ТЗ, плана, issues и макета в момент принятия.
**Затрагивает:** новый скилл `.claude/skills/decision/`, корневой `CLAUDE.md`
(«Карта документации»), скиллы `research`, `prd`
**Задачи:**

- [x] Скилл `/decision <источник> <решение>`: читает ТЗ, план текущей фазы,
      открытые issues и `docs/design/`; предлагает дифф по всем четырём;
      применяет после подтверждения одним коммитом в main.
- [x] «Карта документации»: research — «решения фичи, правятся `/decision`»
      вместо «снапшот с врезками»; из `plan-phase` и `prd` убрать «отступления
      — в сообщении коммита».
- [x] Две точки вызова записаны там, где они происходят: в памяти
      дизайн-трека (конец раунда) и в «Коммиты и PR» корневого `CLAUDE.md`
      (после мержа PR с правками ревью — человек).

      (правило корневого `CLAUDE.md`, на него ссылаются `prd`, `research`,
      `decision`); решение, которое не может принять модель, уходит
      человеку анкетой этого формата.

**Когда готова:** следующий раунд на холсте заканчивается коммитом
`/decision`, а не записью в память.
