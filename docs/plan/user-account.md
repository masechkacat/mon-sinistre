# Plan: Аккаунт пострадавшего

**PRD**: docs/prd/user-account.md
**Research**: docs/research/user-account.md (22.08.2026). Технические решения
(правила пароля CNIL cas n° 2 с SourceReference, bcrypt из зависимостей,
access в теле + refresh в httpOnly-cookie с ротацией, глобальный guard с
`@Public()`, счётчики по HMAC-хешу адреса, чистка cron с индексами в той же
миграции, сессия web в памяти слоя API) приняты там; задачи ниже их применяют,
а не перевыбирают. Отступления реализации фиксируются врезкой «Исправлено при
реализации» в самом отчёте.
**Дата**: 2026-08-22

Новых зависимостей нет ни одной (auth-стек установлен с самого начала);
единственное офлайн-предусловие Ralph Loop — секрет `ACCOUNT_EMAIL_HASH_SECRET`
в локальном `.env` до фазы 4.

## Фаза 1: Регистрация, подтверждение, вход (Tracer Bullet)

**Цель:** сквозной путь через contracts → базу → API: человек регистрируется,
получает письмо, подтверждает адрес и входит, получая рабочую пару токенов.
**Затрагивает:** contracts, db, api
**Задачи:**

- [ ] Contracts: константы пароля (`PASSWORD_MIN_LENGTH`, `PASSWORD_MAX_BYTES`,
      `PASSWORD_MIN_CHAR_CLASSES`) с `SourceReference` на délibération CNIL
      2022-100, `ACCOUNT_CONFIRM_TTL_DAYS`, типы auth-ответов. **Проверяется
      тестами (до кода):** валидатор пароля принимает «Abc12345», отклоняет
      «abc12345» (2 категории), 7 символов и строку длиннее 72 байт (байты,
      не символы — проверка на многобайтовой строке).
- [ ] Миграция `prisma migrate`: `User` (email `unique`, passwordHash,
      confirmedAt, confirmTokenHash `unique`, confirmExpiresAt, createdAt) и
      `RefreshToken` по модели данных § 5; поля подтверждения вносятся в
      `docs/research/data-model.md` § 5 тем же коммитом. **Проверяется тестами
      (до кода):** повторная вставка email даёт P2002; каскад User →
      RefreshToken.
- [ ] Регистрация: нормализация email, валидация пароля DTO, bcrypt-хеш
      (`SALT_ROUNDS`, умолчание 12), токен подтверждения по образцу veille
      (в базе — SHA-256-хеш), письмо через `MailService.send()`; email и
      пароль не попадают в логи. **Проверяется тестами (до кода):** аккаунт
      создан неподтверждённым; письмо содержит ссылку с токеном; « User@X.fr »
      и «user@x.fr» — один аккаунт; в логах прогона нет адреса.
- [ ] Подтверждение: эндпоинт активации по токену (мутация — POST; GET ничего
      не меняет), проверка срока в самом запросе. **Проверяется тестами (до
      кода):** до активации вход с верной парой отклонён; активация
      идемпотентна — повторный вызов отвечает «уже активен» без ошибки;
      просроченный или неизвестный токен — «lien invalide» без раскрытия
      причины.
- [ ] Вход: passport-local по email+паролю, access в теле ответа, refresh —
      httpOnly-cookie (`path=/auth`, `SameSite=Strict`, `secure` вне dev),
      строка `RefreshToken` с хешем. **Проверяется тестами (до кода):** ответ
      на несуществующий email и на неверный пароль неразличим; успешный вход
      отдаёт access и ставит cookie; в логах нет пароля.

**Когда готова:** интеграционный тест проходит цепочку регистрация → письмо →
активация → вход и получает рабочий access; вход до активации невозможен.

## Фаза 2: Сессия: refresh, выход, guard, удаление аккаунта

**Цель:** сессия живёт 30 дней без повторного ввода пароля, приложение получает
защищённый периметр, аккаунт можно удалить (RGPD).
**Затрагивает:** contracts, api
**Задачи:**

- [ ] Refresh с ротацией: новый `RefreshToken` (30 дней) + revoke старого;
      повторное использование отозванного токена — revoke всех токенов
      пользователя. **Проверяется тестами (до кода):** после ротации старый
      refresh отклонён; access обновляется без пароля; reuse отозванного
      гасит всю цепочку; `SESSION_INACTIVITY_DAYS = 30` — константа contracts.
- [ ] Выход: revoke refresh-токена и очистка cookie. **Проверяется тестами
      (до кода):** после выхода refresh отклонён; повторный выход не даёт
      ошибку.
- [ ] Глобальный `JwtAuthGuard` через `APP_GUARD` + декоратор `@Public()` на
      всех существующих публичных эндпоинтах (veille, changement, здоровье,
      auth-формы). **Проверяется тестами (до кода):** эндпоинт без `@Public()`
      отвечает 401 без токена; интеграционные тесты veille и монитора остаются
      зелёными — забытая аннотация ломает их, а не остаётся незамеченной.
- [ ] Эндпоинт текущего пользователя (email для espace personnel).
      **Проверяется тестами (до кода):** с валидным access возвращается email
      владельца токена; без токена — 401.
- [ ] Удаление аккаунта: подтверждённое действие вошедшего пользователя;
      каскад сносит RefreshToken (и PasswordReset с фазы 3). **Проверяется
      тестами (до кода):** после удаления строк пользователя нет в базе
      (проверка запросом), вход невозможен, refresh отклонён; повторная
      регистрация тем же адресом создаёт новый пустой аккаунт.

**Когда готова:** пользователь остаётся вошедшим через ротацию refresh в
пределах 30 дней неактивности; любой новый эндпоинт по умолчанию требует
токен; удаление аккаунта необратимо и немедленно.

## Фаза 3: Сброс пароля и повторная регистрация

**Цель:** забытый пароль и повторная форма регистрации перестают быть тупиками —
оба сценария заканчиваются письмом с рабочей ссылкой.
**Затрагивает:** contracts, db, api
**Задачи:**

- [ ] Миграция: `PasswordReset` (userId cascade, tokenHash `unique`,
      expiresAt, usedAt) + `PASSWORD_RESET_TTL_HOURS = 24` в contracts;
      таблица вносится в `docs/research/data-model.md` тем же коммитом.
      **Проверяется тестами (до кода):** каскад User → PasswordReset.
- [ ] Запрос сброса: письмо со ссылкой только существующему адресу, ответ
      формы одинаков для существующего и несуществующего. **Проверяется
      тестами (до кода):** оба ответа неразличимы; письмо уходит только
      существующему; в логах нет адреса.
- [ ] Смена пароля по токену: валидация нового пароля теми же правилами,
      одноразовость (`usedAt`), проверка срока в запросе, revoke всех
      refresh-токенов пользователя. **Проверяется тестами (до кода):**
      использованная и просроченная ссылка — «lien invalide» без раскрытия
      причины; после смены старый refresh отклонён, вход по новому паролю
      работает.
- [ ] Повторная регистрация неподтверждённым адресом: перезапись passwordHash
      последней формой, продление `confirmExpiresAt`, новое письмо
      подтверждения (перевыпуск хешей — только при фактической отправке, как
      в veille). **Проверяется тестами (до кода):** второго аккаунта нет;
      действует пароль последней формы; срок отсчитан заново.
- [ ] Повторная регистрация подтверждённым адресом: аккаунт не меняется, ответ
      формы неотличим от ответа новому адресу, на адрес уходит письмо «у вас
      уже есть аккаунт» со ссылкой запроса сброса. **Проверяется тестами (до
      кода):** ответы неразличимы; passwordHash не изменился; письмо содержит
      путь запроса сброса.

**Когда готова:** сценарии «забыл пароль» и «регистрируюсь второй раз» из PRD
проходят целиком, ни один ответ API не раскрывает существование адреса.

## Фаза 4: Лимиты и чистка

**Цель:** перебор паролей и спам письмами ограничены по букве CNIL, база не
хранит ни просроченного, ни неподтверждённого.
**Затрагивает:** contracts, db, api
**Задачи:**

- [ ] Миграция: `AccountFormEmail` и `LoginAttempt` (emailHash, метка времени)
      **с частичными индексами всех `deleteMany` чистки в той же миграции**;
      общая HMAC-утилита адреса (секрет — параметром) выносится в общий модуль
      и переиспользуется veille без изменения поведения;
      `ACCOUNT_EMAIL_HASH_SECRET` — в `env.validation.ts` и `.env.example`
      одним коммитом. **Проверяется тестами (до кода):** утилита даёт прежние
      значения на секрете veille (совместимость счётчика).
- [ ] Лимит 5 писем аккаунта за скользящие 24 часа: счётчик в auth-сервисе
      перед `send()`, строка — до отправки и вне транзакции; константы —
      contracts. **Проверяется тестами (до кода):** шестое письмо подавлено,
      ответ формы обычный; письма veille под лимит не подпадают.
- [ ] Лимит попыток входа: 10 неудач за час по HMAC-хешу адреса → 429
      одинаково для существующего и несуществующего адреса; поверх — жёсткий
      `@Throttle` по IP на auth-эндпоинты. **Проверяется тестами (до кода):**
      11-я попытка — 429 и для несуществующего адреса; успешный вход до
      порога работает; константы — contracts.
- [ ] Чистка `@Cron(EVERY_HOUR)`: неподтверждённые User старше 7 дней
      (каскад), просроченные PasswordReset, истёкшие RefreshToken, счётчики
      старше окна. **Проверяется тестами (до кода):** неподтверждённый
      8-дневный User отсутствует в базе после тика (проверка запросом),
      подтверждённый — на месте; тест зовёт метод напрямую, не ждёт cron.

**Когда готова:** все счётчики и сроки из PRD работают и подтверждены
интеграционными тестами; API-часть PRD закрыта целиком.

## Фаза 5: Страницы web

**Цель:** человек проходит все сценарии PRD в браузере: регистрируется,
подтверждает, входит, сбрасывает пароль, видит espace personnel, удаляет
аккаунт.
**Затрагивает:** web
**Задачи:**

- [ ] Сессия в слое `src/lib/api/`: access в памяти (не в браузерном
      хранилище), тихий `POST /auth/refresh` с `credentials: 'include'` при
      старте и при 401, редирект на вход при провале. **Проверяется тестами
      (до кода):** после перезагрузки страницы вошедший остаётся вошедшим;
      после выхода защищённая страница недоступна — в том числе кнопкой
      «назад» (bfcache).
- [ ] Страницы регистрации и подтверждения: форма с валидацией пароля
      константами contracts (сообщение называет все требования сразу),
      страница токена с единственной кнопкой — GET не активирует.
      **Проверяется тестами (до кода):** после регистрации — состояние
      «проверьте почту»; переход по ссылке без нажатия не активирует; после
      нажатия — «compte activé».
- [ ] Страница входа и выход: ошибка входа — одно французское сообщение
      (`role="alert"`), выход из espace personnel. **Проверяется тестами (до
      кода):** неверная пара — сообщение об ошибке, объявляемое скринридером;
      после входа — espace personnel.
- [ ] Страницы «mot de passe oublié» и нового пароля по токену из ссылки.
      **Проверяется тестами (до кода):** запрос сброса всегда отвечает
      «письмо отправлено, если адрес существует»; форма нового пароля с той
      же валидацией; успешная смена ведёт на вход.
- [ ] Espace personnel: email пользователя, выход, удаление аккаунта с
      подтверждением действия. **Проверяется тестами (до кода):** удаление
      требует явного подтверждения; после удаления — публичная страница и
      невозможность войти.

**Когда готова:** сценарии PRD проходят в браузере на прод-сборке; каждая
страница фазы проходит axe без ошибок и полностью проходима с клавиатуры; все
строки — французские, из файлов локализации.
