**План**: docs/plan/harness-v2.md (фазы пишутся после этого отчёта)
**Дата**: 2026-10-13

Разбор полётов после закрытия десяти фич и фазы 8 dossier-preliminaire.
Источники: 32 смерженных PR #181–#285 (01.09–13.10), транскрипты 29 сессий
Ralph фазы 7–8, аудит всех `CLAUDE.md`, `ralph.md`, агентов и скиллов,
инвентаризация маршрутов `apps/web`. Цифры ниже — база, с которой
сверяется каждая фаза плана.

## Решения

### Горизонт: issues только на одну фазу, UI-фаза — после принятого макета

**Решение:** `plan-phase` даёт план фаз описанием; `issues` создаёт issues
только для ближайшей фазы. Фаза с UI не стартует, пока её экран не принят на
холсте и не лежит в `docs/design/<экран>.html` — issues ссылаются на файл.
Поле «Проверяется тестами (до кода)» в шаблоне задачи становится
необязательным; «Когда готова» называет только проверяемое командами из
`allowedTools`.
**Почему:** 05.10 отменена фаза 3 design-system, 10.10 её PR #241 смержен —
очередь была создана раньше решения, и никто её не пересмотрел. Экран
`/dossier` в коде — состояние до тура 13g, дизайн с тех пор менялся трижды
(13g → 14 → 16b). Ralph не видит Claude Design (артефакты за логином) и
строит по тексту.
**Отвергнуто:** журнал решений (пассивен, уже удалялся); план «всё вперёд»
с ручной сверкой (не выполняется, проверено на двух фичах).

### Адресат: скилл `/decision` в двух точках

**Решение:** скилл принимает решение и его источник (раунд дизайна, ревью
PR) и правит ТЗ, план текущей фазы, открытые issues, макет в `docs/design/`.
Вызывается человеком в конце раунда на холсте и после мержа PR с правками.
Правило «research — снапшот с врезками» уходит: решения фичи правятся этим
скиллом в самом отчёте.
**Почему:** правда живёт в шести местах (ТЗ, PRD, research, план, issues,
память) плюс макеты; «врезка задним числом» узаконивает расхождение.

### Проверки вместо прозы

**Решение:** повторившаяся находка переводится в тест, lint или строку
агента, абзац удаляется; свой шаблон ревью с этапом продукта вместо
superpowers. Список — фаза 3 плана.
**Почему:** прозу модель читает и забывает, проверку не обходит: `touch`
повторился в трёх PR после пятикратно записанного правила.

### Бюджет контекста

**Решение:** старт итерации читает меньше 800 строк; каждое правило — в
одном месте; раздел «Тестирование» получает критерий отказа от теста.
Список — фаза 4 плана.
**Почему:** 1 300–1 600 строк, из них ~90 пересказы и четыре прямых
противоречия (`build:contracts` перед тестами, список хука, список
разрешённых скриптов, список модулей с `CLAUDE.md`).

### Дисциплина чтения

**Решение:** файл читается один раз; повторная сверка — диапазоном
(`Grep`, `sed -n`), после правки файл не перечитывается. Правила чтения
и проверки изменённого поведения — в `ralph.md` §§ 1, 3.
Задачи плана не дробятся ради цены: одна задача — одно
связное изменение со своими тестами, как и было.
**Почему:** стоимость итерации — сумма контекста по ходам, и контекст растёт
на ~1k токенов за ход: к первой правке 105–167k при старте 37k, к коммиту
143–241k (фаза 5, четыре итерации). Разведка — 35–45 ходов в каждой
итерации независимо от размера issue; `detail.spec.ts` читался 3–5 раз за
сессию. Стартовые инструкции — несколько тысяч токенов из этих ста
пятидесяти. По 36 итерациям фаз 7–8 и 5: цена ≈ 4,4 млн + 2,1 млн на 100
строк диффа (Spearman 0,93 с объёмом диффа); на 100 строк уходит 13 млн при
диффе до 100 строк и 2,5 млн при диффе больше 600 — дробление задач
умножает фиксированную часть. Признаки текста issue (число пунктов, спеков,
букв ZOMBIES) объём диффа не предсказывают (Spearman ≤ 0,56).
**Отброшено:** лимит файлов на issue — число файлов до работы неизвестно;
дробление задач плана — дороже; снижение `maxBudgetUsd` — обрезает большую
задачу на последних ходах (#293, 86 файлов не закоммичены).

### Замер встроен в цикл

**Решение:** `metrics.js` формирует отчёт PR из всех сохранённых попыток фазы,
включая неудачные и выполненные предыдущими запусками. JSON-result CLI даёт
оценку стоимости в USD и usage; новый, кешированный вход и выход сохраняются
раздельно. Нет результата — нет данных, а не нулевая стоимость. Старые
транскрипты доступны через `--sessions`; их контекст-токены не денежная цена,
а число сообщений не равно `num_turns` CLI: базу выше нельзя напрямую
сравнивать с новым счётчиком ходов.

Локальный отчёт не обращается к GitHub или модели:

```sh
node .claude/metrics.js --list-runs
node .claude/metrics.js --runs all
node .claude/metrics.js --runs feature-a/phase-1,feature-a/phase-2 --compare feature-b/phase-1 --json
```

Выборки задаются именами веток из списка, без повторов и пересечений.
JSON имеет `version: 1`, `current`, `baseline` и `comparison`; без базы два
последних поля равны `null`. Повреждённый или отсутствующий выбранный журнал
даёт ошибку, чтение ничего не создаёт и не изменяет.

«Принято» означает завершённую автоматическую приёмку, push и перевод
карточки, не мерж или одобрение человеком. Стоимость принятой задачи —
расход **всех сессий реализации выборки**, включая неудачные и ещё не принятые
задачи, делённый на число принятых. Отдельное ревью фазы и работа вне Ralph
не входят в этот счётчик. Доля принятия одной попыткой считается от всех
начатых задач; ручное подтверждение кандидата не считается таким успехом.

Времена агента и каждого прогона приёмки суммируются, включая повторы.
Медиана времени до принятия включает паузы между попытками и ручные ожидания.
Журнал записывает SHA запускающего харнесса, выбранную модель и события
остановки; повторная остановка на одной причине — отдельное событие.
Для старых попыток неизвестная история приёмки и остановок не восстанавливается
догадками. При неполных данных полная оценка и её дельта — `null`, известная
часть и покрытие выводятся отдельно; процент от нулевой базы не определён.
Это описательное сравнение, не доказательство экономии: задачи, модели и
окружение могут различаться.

### Приёмка и возобновление

`verificationCommands` в `.claude/ralph.config.json` — единственный список
автоматической приёмки текущей фазы, массивы `["npm", "run", "<script>"]`.
До запуска проверяется наличие скриптов; после коммита оркестратор выполняет
их без shell и проверяет неизменность SHA и чистоту дерева. Красная проверка
останавливает push и перевод карточки. Интерактивное UI-ревью остаётся
обязанностью агента, а не заменяется успешным выходом npm.

Журнал в каталоге `git rev-parse --git-path ralph` хранит этапы и метрики,
не ответы модели. Lock в Git-каталоге запрещает второй одновременный запуск
в том же worktree. Обычный повтор запуска продолжает приёмку/push/доску,
не реализацию; после опубликованного SHA повторяется только перевод карточки.
После ошибки или потери JSON-result кандидат требует отдельного
`node .claude/ralph.js --verify-candidate`: ровно одна фаза в конфиге,
приёмка и публикация без вызова модели и перехода к следующей задаче.
Перед подтверждением проверь, что прежний процесс агента завершён.
Незакоммиченные изменения или потеря результата без коммита требуют ручного
разбора: новый агент не запускается, журнал и рабочие файлы сохраняются.
Лимит процесса — `iterationTimeoutMs` (по умолчанию два часа).
Отчёт dry-reviewer относится к паре base/head SHA, а не ко всей жизни PR.

## Что из готового не берётся

- `open-code-review` (Alibaba): экономия только при отдельном API-ключе,
  правила про NPE/XSS/SQLi, режим без ключа не экономит.
- `ponytail`: «lean» покрывает лишь дубль код—код; `shortcut:`-комментарии и
  реестр долга против правил проекта.
- `context-mode`: `ctx_execute` — произвольное исполнение кода, ломает
  модель безопасности `ralph.md` § 6; хук правит `~/.claude/settings.json`.
- `jevgrep`: семантический поиск для больших незнакомых баз; на ~500 файлах
  с картой в `CLAUDE.md` выигрыша нет, бенчмарк автора в 0.5.0 — ноль.
- Open Design, OpenPencil, Pencil: замена Claude Design или векторный
  редактор; узкое место не в инструменте, а в доставке решений до очереди.
- Spec Kit, BMAD: тот же водопад, петель «горизонт» и «адресат» в них нет.

## Ограничения и риски

- Журнал локален worktree: на другой машине история попыток недоступна.
  Приёмка не восстанавливает окружение; база и зависимости должны быть
  подготовлены. После перезапуска до публикации проверки выполняются заново.
- Доля PR с правками считается по слову «ревью/review» в сообщениях коммитов
  — коммит, правящий по ревью молча, не засчитается: против ручного разбора
  (20 из 32) метрика занижает на ~10 %.
- Срезание горизонта удлиняет паузы между фазами: каждая UI-фаза ждёт
  принятого макета. Это цена, а не побочный эффект.
