## Решения

### Горизонт: issues только на одну фазу, UI-фаза — после принятого макета

**Решение:** `plan-phase` даёт план фаз описанием; `issues` создаёт issues
только для ближайшей фазы. Фаза с UI не стартует, пока её экран не принят на
холсте и не лежит в `docs/design/<экран>.html` — issues ссылаются на файл.
Поле «Проверяется тестами (до кода)» в шаблоне задачи становится
необязательным; «Когда готова» называет только проверяемое командами из
`allowedTools`.
**Почему:** 05.10 отменена фаза 3 design-system, 10.10 её PR #241 смержен —
очередь была создана раньше решения, и никто её не пересмотрел. Экран
`/dossier` в коде — состояние до тура 13g, дизайн с тех пор менялся трижды
(13g → 14 → 16b). Ralph не видит Claude Design (артефакты за логином) и
строит по тексту.
**Отвергнуто:** журнал решений (пассивен, уже удалялся); план «всё вперёд»
с ручной сверкой (не выполняется, проверено на двух фичах).

### Адресат: скилл `/decision` в двух точках

**Решение:** скилл принимает решение и его источник (раунд дизайна, ревью
PR) и правит ТЗ, план текущей фазы, открытые issues, макет в `docs/design/`.
Вызывается человеком в конце раунда на холсте и после мержа PR с правками.
Правило «research — снапшот с врезками» уходит: решения фичи правятся этим
скиллом в самом отчёте.
**Почему:** правда живёт в шести местах (ТЗ, PRD, research, план, issues,
память) плюс макеты; «врезка задним числом» узаконивает расхождение.

### Проверки вместо прозы

**Решение:** повторившаяся находка переводится в тест, lint или строку
агента, абзац удаляется; свой шаблон ревью с этапом продукта вместо
superpowers. Список — фаза 3 плана.
**Почему:** прозу модель читает и забывает, проверку не обходит: `touch`
повторился в трёх PR после пятикратно записанного правила.

### Бюджет контекста

**Решение:** старт итерации читает меньше 800 строк; каждое правило — в
одном месте; раздел «Тестирование» получает критерий отказа от теста.
Список — фаза 4 плана.
**Почему:** 1 300–1 600 строк, из них ~90 пересказы и четыре прямых
противоречия (`build:contracts` перед тестами, список хука, список
разрешённых скриптов, список модулей с `CLAUDE.md`).

### Замер встроен в цикл

**Решение:** три числа базы считает `metrics.js`, два из них цикл кладёт
в тело PR фазы. Это фаза 0: без неё остальные фазы — вера.
**Почему:** это не первый разбор полётов, и все прежние были по ощущению.

## Что из готового не берётся

- `open-code-review` (Alibaba): экономия только при отдельном API-ключе,
  правила про NPE/XSS/SQLi, режим без ключа не экономит.
- `ponytail`: «lean» покрывает лишь дубль код—код; `shortcut:`-комментарии и
  реестр долга против правил проекта.
- `context-mode`: `ctx_execute` — произвольное исполнение кода, ломает
  модель безопасности `ralph.md` § 6; хук правит `~/.claude/settings.json`.
- `jevgrep`: семантический поиск для больших незнакомых баз; на ~500 файлах
  с картой в `CLAUDE.md` выигрыша нет, бенчмарк автора в 0.5.0 — ноль.
- Open Design, OpenPencil, Pencil: замена Claude Design или векторный
  редактор; узкое место не в инструменте, а в доставке решений до очереди.
- Spec Kit, BMAD: тот же водопад, петель «горизонт» и «адресат» в них нет.

## Ограничения и риски

- `metrics.js` считает по транскриптам Claude Code в `~/.claude/projects/`;
  их чистка или смена формата обнулит замер, не сломав цикл.
- Доля PR с правками считается по слову «ревью/review» в сообщениях коммитов
  — коммит, правящий по ревью молча, не засчитается: против ручного разбора
  (20 из 32) метрика занижает на ~10 %.
- Срезание горизонта удлиняет паузы между фазами: каждая UI-фаза ждёт
  принятого макета. Это цена, а не побочный эффект.
