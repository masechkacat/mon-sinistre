# Research: Фундамент клиента и главная страница

**План**: docs/plan/web-foundation.md
**Дата**: 2026-08-04

> **Снапшот на дату.** Отчёт фиксирует решения на момент ресерча; расхождения
> при реализации отмечаются врезкой «Исправлено при реализации», как в
> docs/research/emails.md.

Стек, от которого отталкиваются решения: Next.js 16.2 (App Router, `src/app/`),
React 19.2, Tailwind CSS 4.1, TanStack Query 5.101 (установлен, не подключён),
eslint 9 + `eslint-config-next` 16 (flat config), Node 24. Тестов и
тест-раннера в `apps/web` нет — их выбор входит в этот отчёт.

## Решения

### Тест-раннер и axe-инфраструктура

**Решение:** Playwright Test (`@playwright/test` ^1.62) +
`@axe-core/playwright` ^4.12, браузер — только chromium; прогон против
**прод-сборки** (`next build && next start` в `webServer`); запуск — отдельная
корневая команда `npm run test:web`, **не** pre-commit.
**Почему:**

- Контраст (правило `color-contrast` axe) вычисляется только по реальному
  рендеру — нужен настоящий браузер; jsdom-обвязки (jest-axe) контраст не
  проверяют. Playwright закрывает и остальные проверки плана: клавиатурный
  проход, эмуляция тем и `prefers-reduced-motion`, вьюпорт 320 px и масштаб
  200 %, `scrollWidth`.
- Прод-сборка обязательна, а не желательна: в dev-режиме Next подменяет
  `not-found` и `error` собственным overlay'ем — тесты фазы 3 против dev-сервера
  проверяли бы не то, что увидит пользователь.
- Один chromium: проверяемое (контраст, landmarks, порядок фокуса) не зависит
  от движка, а каждый лишний браузер — минуты прогона и сотни мегабайт.
- В pre-commit не включать: сборка плюс браузерный прогон — минуты, хук
  перестанут запускать. Хук по-прежнему гоняет `lint` (куда встаёт контроль
  литералов — ниже) и `npm test`. Прогон `test:web` — обязательный критерий
  «когда готова» каждой фазы: Ralph Loop запускает его как проверку итерации
  (правки конфига — в разделе «Команды и предусловия по фазам»).
- Playwright MCP уже используется в проекте для визуальной проверки — команда
  разработчика и тесты будут на одном инструменте.

**Отброшено:**

- jest-axe / vitest + jsdom — не проверяют контраст, не рендерят темы, не
  умеют клавиатурный проход; вторая тест-инфраструктура рядом с Playwright
  всё равно понадобилась бы для фаз 2–5.
- Cypress + cypress-axe — тяжелее, медленнее, вторая экосистема; Playwright уже
  в проекте как MCP.
- Lighthouse CI — метрики и аудит, а не падающий тест с точным правилом axe.

**Как применять:**

- `apps/web/playwright.config.ts`: `testDir: './tests'`,
  `webServer: { command: 'npm run build && npm run start', port: 3000, env: { TEST_ROUTES: '1' }, reuseExistingServer: false, timeout: 180_000 }`.
  `reuseExistingServer: false` осознанно: подхваченный dev-сервер сделал бы
  тесты фазы 3 ложно-зелёными.
- Общий хелпер `tests/a11y.ts`:

  ```ts
  export async function expectNoAxeViolations(page: Page) {
    const results = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa'])
      .analyze();
    expect(results.violations).toEqual([]);
  }
  ```

  `color-contrast` входит в тег `wcag2aa` — отдельно включать не нужно.

- Список публичных страниц — один массив в `tests/pages.ts`; общий тест
  итерирует «каждая страница × обе темы». Новая страница = одна строка в
  массиве; фазы 2–4 только пополняют его.
- Смоук самой проверки (задача фазы 1): тест делает
  `page.setContent('<img src="x.png">')` (картинка без `alt`) и ожидает, что
  `expectNoAxeViolations` падает. Отдельная страница в приложении не нужна.

### Обе темы и prefers-reduced-motion в тестах

**Решение:** `page.emulateMedia({ colorScheme: 'dark' | 'light' })` для тем,
`page.emulateMedia({ reducedMotion: 'reduce' })` + сверка
`getComputedStyle().transitionDuration` для анимаций.
**Почему:** темы реализуются на media query (решение ниже), и эмуляция
Playwright переключает их без прикосновения к DOM; это же связывает выбор
механизма темы с тестируемостью.
**Отброшено:** прогон двух сборок с разными классами на `<html>` — необходим
только при class-стратегии темы, которую не берём.

### Темы: системная, через `prefers-color-scheme`, без переключателя

**Решение:** токены тем — CSS-переменные в `globals.css`; тёмные значения — в
`@media (prefers-color-scheme: dark)`. Переключателя темы нет; `next-themes` не
ставится.
**Почему:**

- PRD требует «светлая и тёмная темы с контрастом AA», но не переключатель;
  «дизайн-система сверх компонентной базы» — вне скоупа. Системная тема
  выполняет требование нулём клиентского JS.
- Нет переключателя — нет FOUC, нет хранения предпочтения (cookie /
  localStorage), нечего объявлять скринридеру, нечему ломаться без JS. Для
  аудитории «пожилые, в стрессе» лишний орган управления — цена без выгоды:
  тема и так следует настройке устройства.
- Tailwind 4 по умолчанию строит вариант `dark:` на `prefers-color-scheme` —
  media-стратегия «бесплатна», class-стратегия потребовала бы
  `@custom-variant`.
- Тестируется одним `emulateMedia` (решение выше).

**Отброшено:** `next-themes` + класс `.dark` + переключатель — новая
зависимость, клиентский компонент, инлайн-скрипт против FOUC и хранение
предпочтения ради возможности, которой нет в требованиях. Если переключатель
когда-нибудь попадёт в PRD — переход известен: `next-themes`,
`@custom-variant dark`, перевод тестов с `emulateMedia` на выставление класса.
**Как применять:** shadcn init генерирует тёмные токены в классе `.dark` —
перенести их содержимое в `@media (prefers-color-scheme: dark) { :root { … } }`
тем же коммитом, класс `.dark` удалить.

### shadcn/ui на Base UI: инициализация

**Решение:** `npx shadcn@latest init` (CLI ^4.16) в `apps/web`, при
инициализации выбрать **Base UI** (дефолт CLI с июля 2026 — но выбор
подтвердить явно, требование `apps/web/CLAUDE.md`), base color — neutral.
Компоненты добавляются `npx shadcn@latest add <имя>` — обе команды выполняет
владелец (`npx` запрещён Ralph Loop); фазам этой фичи достаточно `button`,
`card`, `alert`.
**Почему:** зафиксировано в PRD и `apps/web/CLAUDE.md`, не переисследуется.
Neutral — нейтральная база, бренд-палитра вне скоупа PRD.
**Отброшено:** выбор Radix-варианта — прямо запрещён `apps/web/CLAUDE.md`.
**Как применять:**

- init перепишет `globals.css` — **сохранить существующие блоки**: skip-link,
  `:focus-visible`, `prefers-reduced-motion` (базовые a11y-правила, обязаны
  пережить любую дизайн-работу — комментарий в самом файле).
- Дефолтные значения токенов neutral не считать проверенными: контраст
  подтверждает axe-прогон в обеих темах; если `muted-foreground` и подобные не
  дотягивают до 4.5:1 — корректировать значения токенов, а не отключать
  правило.
- Глобальное отключение анимаций при `prefers-reduced-motion` уже реализовано
  в `globals.css` — задача фазы 1 сводится к «не потерять при init» и покрыть
  тестом.

### Механизм локализации: типизированный TS-словарь

**Решение:** `src/i18n/fr.ts` — объект `as const`, параметры — функции-поля;
даты — единственная утилита `formatDateFr` в `src/i18n/date.ts` на
`Intl.DateTimeFormat('fr-FR')`. Никакой библиотеки.
**Почему:** то же решение, что в `apps/api` (docs/research/emails.md, раздел
«Механизм локализации»), и аргументы те же: язык ровно один, многоязычность —
вне скоупа PRD, а TypeScript даёт то, чего JSON-словари не дают, — пропущенный
ключ и забытый параметр ломают компиляцию, не рендер. Один образец локализации
на весь монорепозиторий вместо двух механизмов.
**Отброшено:** `next-intl` — middleware, резолвинг локали, `NextIntlClientProvider`
и JSON без типов ради единственной локали; `react-i18next` — то же плюс
runtime-словарь в бандле клиента; свой резолвер поверх JSON — теряет типизацию,
ничего не добавляя.
**Как применять:**

- Импорт напрямую и в серверных, и в клиентских компонентах
  (`import { fr } from '@/i18n/fr'`) — состояния нет, провайдер не нужен;
  словарь попадает в серверный рендер и в бандл естественным образом.
- `metadata` в `layout.tsx` берёт строки из того же словаря.
- Подписи к enum-значениям contracts (правило `apps/web/CLAUDE.md`) — ветки
  этого же объекта; второго файла с французскими строками не заводить.
- Даты: вход — `IsoDate` из contracts, не `Date`:

  ```ts
  const formatter = new Intl.DateTimeFormat('fr-FR', {
    dateStyle: 'long',
    timeZone: 'UTC',
  });
  export function formatDateFr(date: IsoDate): string {
    return formatter.format(new Date(`${date}T00:00:00Z`));
  }
  ```

  `timeZone: 'UTC'` парный к суффиксу `Z`: `IsoDate` не несёт времени, и пара
  «UTC туда — UTC обратно» исключает сдвиг на день в любой таймзоне браузера.

### Контроль «ни одной французской строки в компонентах»

**Решение:** `eslint-plugin-i18next` ^6.1 (dev-зависимость), правило
`i18next/no-literal-string` в `mode: 'jsx-only'` с проверкой текстовых
атрибутов (`alt`, `aria-label`, `aria-description`, `title`, `placeholder`);
`src/i18n/**` исключён из правила.
**Почему:** правило создано ровно под эту задачу: проверяет JSX-текст и
названные атрибуты, игнорируя технические (`className` с Tailwind-классами —
литерал в каждой строке разметки). Встаёт в существующий flat config, а значит
в уже работающий конвейер: `npm run lint` в pre-commit подхватит его без новой
команды. Обоснование новой зависимости: уже установленный
`react/jsx-no-literals` (в составе `eslint-config-next`) атрибуты либо не
проверяет вовсе — дыра именно в aria-строках, критичных для a11y-продукта, —
либо (`noAttributeStrings`) запрещает `className`, что с Tailwind неприменимо.
**Отброшено:** `react/jsx-no-literals` — см. выше; самописный скрипт-грепалка —
не знает JSX-контекста, ловил бы и Tailwind-классы, и `data-testid`.
**Как применять:**

```js
// eslint.config.mjs
import i18next from 'eslint-plugin-i18next';

export default defineConfig([
  // …существующие конфиги…
  {
    files: ['src/**/*.tsx'],
    plugins: { i18next },
    rules: {
      'i18next/no-literal-string': [
        'error',
        {
          mode: 'jsx-only',
          'jsx-attributes': {
            include: [
              'alt',
              'aria-label',
              'aria-description',
              'title',
              'placeholder',
            ],
          },
        },
      ],
    },
  },
  { files: ['src/i18n/**'], rules: { 'i18next/no-literal-string': 'off' } },
]);
```

Точную семантику `include`/`exclude` подтверждает смоук из задачи фазы 1
(правило обязано упасть на нарочно оставленной французской строке и на
французском `aria-label`) — конфиг корректируется по смоуку, а не по статье.
Правило не видит строк вне JSX (константы, `throw`) — пользовательские строки
туда не попадают по построению: показ любой из них идёт через `fr.ts`.

### Провокация ошибки рендера (фаза 3)

**Решение:** тестовые маршруты за env-флагом: серверный компонент
`src/app/test-erreur/page.tsx` с `export const dynamic = 'force-dynamic'`,
который при `process.env.TEST_ROUTES !== '1'` вызывает `notFound()`, иначе
бросает `Error`. Флаг задаёт только `webServer` Playwright.
**Почему:** ошибка настоящая — через реальный рендер серверного компонента, и
проверяется настоящий `error.tsx` на прод-сборке (в dev его закрывает overlay).
В обычном проде маршрут отдаёт 404 — поверхность не расширяется;
`force-dynamic` не даёт сборке зафиксировать поведение до чтения env.
**Отброшено:** маршрут, бросающий всегда, — попал бы в прод; сборка с
`NODE_ENV=test` — Next жёстко завязан на `production` при `next start`;
инъекция ошибки через невалидные props с клиента — не воспроизводит серверный
путь ошибки.
**Как применять:** `error.tsx` (клиентский, корень `app/`) и
`global-error.tsx` рендерят один общий компонент экрана ошибки — текст из
`fr.ts` не дублируется; e2e-тест покрывает `error.tsx` через `/test-erreur`.
Спровоцировать падение самого корневого layout без порчи прод-кода нельзя —
`global-error.tsx` остаётся без e2e (риск ниже). Страница `not-found`
тестируется без обвязки: переход на несуществующий адрес.

### Структура юридических страниц

**Решение:** две страницы по типовой структуре французских источников; тексты —
черновики в `fr.ts`, вычитка и фактические данные — владелец на ревью PR.

Mentions légales — обязательные блоки (LCEN, loi n° 2004-575 du 21.06.2004,
art. 6; entreprendre.service-public.gouv.fr, fiche F31228, сверено 04.08.2026):

1. Éditeur du site: nom, prénom, adresse, contact (email, téléphone); статус
   «entrepreneur individuel», если применимо.
2. Directeur de la publication.
3. Hébergeur: nom/dénomination, adresse, téléphone.
4. (при регулируемой деятельности — autorité de régulation; к нам не
   относится.)

LCEN art. 6-III-2 даёт непрофессиональному физлицу-издателю право на
анонимность: публикуется только hébergeur, свои данные передаются лишь ему.
Публиковать ли личный адрес — решение владельца на ревью текстов; черновик
готовится с полем éditeur и пометкой об альтернативе.

Politique de confidentialité — обязательные блоки (RGPD art. 13; структура
сверена по обзорам CNIL-практики 04.08.2026, ссылки в PR фазы 4):

1. Responsable de traitement и его контакты.
2. Собираемые данные. Честно по состоянию продукта: на момент фазы 4 сайт не
   собирает ничего — ни аккаунтов, ни аналитики, ни cookies (аналитика — вне
   скоупа PRD; так и написать, это сильная сторона, а не пробел). Раздел про
   email и коммуны появится с фичей veille — там же double opt-in и отписка.
3. Finalités и base légale каждого traitement.
4. Destinataires / sous-traitants (с veille: Scaleway TEM, обработка в ЕС —
   docs/research/emails.md).
5. Durée de conservation.
6. Droits (accès, rectification, effacement, opposition, portabilité) и как их
   реализовать (контакт).
7. Droit de réclamation auprès de la CNIL.

**Отброшено:** генераторы политик и копирование чужих текстов — телега впереди
лошади: текст обязан описывать реальные traitements продукта, которых пока
почти нет.

### Слой обращения к API

**Решение:** TanStack Query 5.101 (установлен) по правилам
`apps/web/CLAUDE.md`; структура слоя — `src/lib/api/`: `config.ts` (базовый
адрес), `client.ts` (fetch-обёртка), `keys.ts` (фабрика ключей запросов);
провайдер — клиентский компонент `src/app/providers.tsx`. Базовый адрес —
`NEXT_PUBLIC_API_URL`, читается ровно в `config.ts`, умолчание —
`http://localhost:3001`.
**Почему:** выбор библиотеки зафиксирован в PRD и `apps/web/CLAUDE.md`;
исследовать здесь нечего, фиксируется только структура, чтобы фаза 5 не
изобретала раскладку. Паттерны Query (создание `QueryClient` в `useState`
внутри провайдера — не на уровне модуля, иначе клиент разделяется между
SSR-запросами; ключи; ретраи) — из скилла **tanstack-query**, который
обязателен перед кодом фазы 5; отчёт их не пересказывает.
**Отброшено:** повторно — ручной `fetch` + `useState` (запрещён CLAUDE.md);
axios — зависимость без выгоды при нативном fetch.
**Как применять:**

- `NEXT_PUBLIC_*` инлайнится в бандл при `next build` — адрес прода задаётся
  на сборке, не на старте; отразить в `apps/web/.env.example` одной
  переменной.
- Ошибка запроса: общий компонент с `role="alert"` и текстом из `fr.ts`
  (правило CLAUDE.md). Тест фазы 5 — тестовый маршрут `src/app/test-requete/`
  за тем же флагом `TEST_ROUTES` (образец фазы 3) с `useQuery`;
  `page.route('**', route.abort())` на адрес API → на странице французское
  сообщение, axe этого состояния зелёный.

## Команды и предусловия по фазам (выполняет владелец)

Ralph Loop не ставит зависимости и не правит `package.json` — всё ниже
выполняется вручную **до** запуска соответствующей фазы.

Перед фазой 1:

```bash
# зависимости (в workspace web)
npm install -D -w @mon-sinistre/web @playwright/test @axe-core/playwright eslint-plugin-i18next
npx playwright install chromium   # при нехватке системных библиотек: --with-deps (sudo)

# shadcn/ui: init + компоненты фаз 2–5 (выбрать Base UI, base color neutral)
cd apps/web && npx shadcn@latest init && npx shadcn@latest add button card alert
```

Правки файлов, недоступных циклу:

- корневой `package.json`: `"test:web": "npm run test --workspace @mon-sinistre/web"`;
- `apps/web/package.json`: `"test": "playwright test"`;
- `.claude/ralph.config.json` → `allowedTools`: добавить
  `"Bash(npm run test:web)"` и MCP-инструменты Playwright
  (`"mcp__playwright__*"`) — без них цикл не выполнит ни прогон тестов, ни
  обязательную визуальную проверку из `apps/web/CLAUDE.md`.

Перед фазами 2–5 новых пакетов не требуется.

## Ограничения и риски

- **`npm run test:web` — минуты, не секунды** (сборка + браузер), поэтому его
  нет в pre-commit. Держится он на двух местах: критерий «когда готова» каждой
  фазы и прогон в Ralph Loop. Если появится CI — команда готова к переносу.
- **shadcn init перезаписывает `globals.css`** — существующие a11y-блоки
  (skip-link, `:focus-visible`, `prefers-reduced-motion`) обязаны пережить
  инициализацию; тест фазы 1 на skip-link и reduced-motion ловит потерю.
- **Контраст дефолтной палитры neutral не гарантирован**: axe-прогон обеих тем
  — арбитр; при нарушении правится значение токена.
- **`global-error.tsx` не покрыт e2e** — падение корневого layout не
