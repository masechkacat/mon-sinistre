# PRD: Veille — жизненный цикл подписки

**Дата**: 2026-08-02
**Статус**: approved <!-- draft → approved → done; в реализацию берётся только approved -->

## Цель

Житель коммуны без аккаунта оставляет email и список коммун, чтобы узнать о
публикации arrêté catastrophe naturelle в день публикации. Эта итерация — только
жизненный цикл подписки (создание, подтверждение, изменение, отписка, удаление);
сама рассылка уведомлений — отдельный PRD вместе с монитором JO.

## Пользовательские сценарии

- Пользователь оставляет email и выбирает одну или несколько коммун → получает
  письмо со ссылкой подтверждения; до подтверждения писем veille не получает.
- Пользователь переходит по ссылке подтверждения → подписка активна, он это видит.
- Пользователь повторно заполняет форму тем же email с другим составом коммун →
  изменение вступает в силу только после подтверждения по новой ссылке; действует
  только последняя выданная ссылка, прежние отвечают «lien invalide»; по ответу
  формы нельзя понять, был ли адрес уже подписан.
- Пользователь нажимает «se désinscrire» в любом письме → подписка и все связанные
  с ней данные удалены немедленно, без дополнительных шагов.
- Пользователь получил письмо-подтверждение на адрес, который сам не оставлял →
  ссылка отписки в этом письме в один клик удаляет все данные, подтверждать
  ничего не нужно.
- Пользователь не подтвердил новую подписку за 7 дней → она удалена; повторная
  подписка начинается заново.
- Пользователь с активной подпиской отправил изменение и не подтвердил его за
  7 дней → изменение отброшено, подписка продолжает действовать в прежнем
  составе.

## В скоупе

- Публичная форма подписки: email + выбор от 1 до 20 коммун поиском (название
  или код INSEE) по локальному справочнику Commune.
- Double opt-in: письмо-подтверждение, активация по ссылке, страница результата.
- Изменение состава коммун повторной отправкой формы (одна veille на адрес),
  также через double opt-in; действует только последняя выданная ссылка
  подтверждения.
- Отписка в один клик из любого письма — включая письмо-подтверждение ещё не
  подтверждённой подписки — с немедленным удалением всех данных подписки.
- Автоматическое удаление подписок, ни разу не подтверждённых за 7 дней.
  Неподтверждённое изменение состава коммун по истечении 7 дней отбрасывается —
  сама подтверждённая подписка не удаляется и действует в прежнем составе.
- Ограничение частоты писем подтверждения: не более 5 на один адрес в сутки;
  при превышении письмо не отправляется, а ответ формы не отличается от
  обычного.
- Защита от перечисления адресов: ответ формы одинаков для нового и существующего
  email.
- Нормализация email (регистр, пробелы) до проверки уникальности.

## Не в скоупе

- Монитор JO и отправка уведомлений в день arrêté (fan-out, идемпотентность
  `VeilleNotification`) — отдельный PRD.
- История CatNat коммуны из Géorisques при выборе коммуны — следующая итерация.
- Импорт справочника Commune и поиск по нему — отдельная фича-предпосылка:
  `docs/prd/commune-referential.md`.
- Личный кабинет наблюдателя: управление подпиской — только через форму и ссылки
  в письмах.
- Связь veille с аккаунтом User.
- Капча/анти-спам формы (вернуться, если появится абьюз).

## Ограничения

- Double opt-in, отписка в один клик, немедленное удаление по запросу — жёсткое
  требование ТЗ § 7 (RGPD).
- Одна подписка на адрес, анти-enumeration, нормализация email, hard delete
  каскадом — по принятой модели данных `docs/research/data-model.md` § 6–7.
- Срок жизни ссылки подтверждения — 7 дней, лимит 20 коммун на подписку и
  5 писем подтверждения на адрес в сутки: продуктовые решения владельца
  (02.08.2026), не юридические сроки, SourceReference не требуется.
- Форма и страницы подтверждения/отписки — WCAG 2.1 AA / RGAA 4.1.2 (ТЗ § 7).
- Язык интерфейса и писем — французский; все строки в файлах локализации.
- Email наблюдателей не попадает в логи (ТЗ § 7).
- Зависимость: справочник Commune загружен и поиск по нему работает — реализуется
  по PRD `docs/prd/commune-referential.md` до этой фичи.

## Критерии готовности

- [ ] Форма принимает email и от 1 до 20 коммун; 0 коммун или больше 20 —
      ошибка валидации; коммуна находится поиском по названию и по коду INSEE
      из локального справочника.
- [ ] До перехода по ссылке подтверждения подписка не считается активной
      (попадание в рассылку — критерий PRD монитора JO).
- [ ] Переход по действующей ссылке активирует подписку; повторный переход по той
      же ссылке даёт тот же результат без ошибки.
- [ ] Повторная отправка формы с существующим email не создаёт вторую подписку;
      новый состав коммун применяется только после подтверждения по новой ссылке,
      до этого действует прежний.
- [ ] После повторной отправки формы действует только последняя ссылка
      подтверждения; переход по любой из прежних отвечает «lien invalide».
- [ ] Ответ формы неразличим для нового и уже подписанного адреса.
- [ ] Email нормализуется: « User@Example.fr » и «user@example.fr» — одна подписка.
- [ ] Переход по ссылке отписки удаляет подписку и связанные данные немедленно,
      без промежуточных подтверждений; повторный переход не даёт ошибку.
- [ ] Ссылка отписки работает и для ни разу не подтверждённой подписки: один
      клик из письма-подтверждения удаляет все данные.
- [ ] Подписка, ни разу не подтверждённая за 7 дней, удаляется автоматически; её
      ссылка подтверждения после этого отвечает «lien invalide» без раскрытия
      причины.
- [ ] Неподтверждённое изменение старше 7 дней отбрасывается: подтверждённая
      подписка не удаляется и продолжает действовать в прежнем составе, ссылка
      изменения отвечает «lien invalide».
- [ ] На один адрес уходит не более 5 писем подтверждения в сутки; при
      превышении ответ формы неотличим от обычного.
- [ ] Email не встречается в логах приложения ни на одном шаге сценариев выше.
- [ ] Форма и страницы подтверждения/отписки проходят axe без ошибок и полностью
      проходимы с клавиатуры.
- [ ] Все пользовательские строки — на французском, в файлах локализации; в
      contracts текстов UI нет.
