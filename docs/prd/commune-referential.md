# PRD: Справочник Commune

**Дата**: 2026-08-02
**Статус**: approved <!-- draft → approved → done; в реализацию берётся только approved -->

## Цель

Локальный справочник коммун Франции — фундамент для всех фич, где фигурирует
коммуна: подписка veille, создание синистра, сопоставление annexes arrêté.
Пользовательская ценность — человек находит свою коммуну поиском по названию или
коду INSEE и не может выбрать несуществующую.

## Пользовательские сценарии

- Пользователь (в форме veille или при создании синистра) вводит начало названия
  коммуны → получает подсказки с названием и département; одноимённые коммуны
  различимы.
- Пользователь вводит точный код INSEE → находит свою коммуну.
- Пользователь вводит название с ошибкой в диакритике или в другом регистре
  («chateau») → находит коммуну («Château-Thierry»).

## В скоупе

- Хранение справочника коммун в базе приложения по принятой модели данных
  (код INSEE, название, département, срок действия кода, преемник, источник).
- Разовый импорт всех коммун актуального COG из geo.api.gouv.fr с фиксацией
  `SourceReference` (источник и дата сверки).
- Повторный запуск импорта безопасен: не создаёт дублей, обновляет изменившиеся
  названия, не удаляет коды, исчезнувшие из ответа источника.
- Поиск/автодополнение по началу названия (без учёта регистра и диакритики) и по
  коду INSEE — доступен без аккаунта, переиспользуется veille и синистром.
  Возвращает только действующие коды (без заполненного `effectiveTo`); подсказки
  ограничены 10 результатами в алфавитном порядке названий. Запрос короче
  2 символов отклоняется валидацией — подсказки по одной букве не выдаются.

## Не в скоупе

- Регулярная (по расписанию) актуализация справочника — появится вместе с
  монитором JO.
- Логика слияний и переименований коммун: поля `effectiveTo` и
  `successorCodeInsee` есть в схеме (модель данных этого требует), но
  заполняются и используются позже — при актуализации и fan-out уведомлений.
- Исторические коды, отсутствующие в актуальном COG, — добавятся, когда парсер
  arrêté встретит их в реальных annexes.
- Arrondissements municipaux Парижа, Лиона и Марселя (собственные коды INSEE,
  в стандартной выдаче коммун geo.api.gouv.fr отсутствуют): annexes arrêté и
  GASPAR ими оперируют, решение о включении в справочник — TBD при работе над
  парсером annexes.
- Collectivités d'outre-mer (Saint-Martin, Saint-Barthélemy): режим CatNat там
  действует, но в выдаче коммун API их может не быть — добавятся тем же путём,
  что исторические коды.
- История CatNat коммуны из Géorisques.
- Какой-либо UI — формы, использующие поиск, принадлежат своим фичам (veille,
  синистр).
- Ограничение частоты запросов к поиску (вернуться, если появится абьюз).

## Ограничения

- Схема — строго по `docs/research/data-model.md` § 3 (Commune): идентичность по
  коду INSEE, история через преемника; устаревшие коды никогда не удаляются.
- Источник — geo.api.gouv.fr (локальная копия в базе — требование ТЗ § 4);
  каждая запись несёт `SourceReference` с датой сверки.
- Изменения схемы БД — только через миграции (ТЗ § 7).
- Поиск обслуживает безаккаунтную форму veille, поэтому доступен без
  аутентификации.
- В contracts нет текстов UI; названия коммун — данные, не переводятся.

## Критерии готовности

- [ ] После импорта число обработанных импортом записей равно числу коммун,
      полученных от источника; ни одна запись не отброшена молча (усечённый
      ответ источника или потеря при вставке — ошибка импорта, не пропуск).
      Коды, сохранённые в базе, но исчезнувшие из ответа источника, в сверке
      не участвуют.
- [ ] Каждая импортированная запись содержит код INSEE, название, код и название
      département, источник и дату сверки.
- [ ] Повторный запуск импорта не создаёт дублей; изменившееся в источнике
      название обновляется на месте, код остаётся.
- [ ] Код, отсутствующий в свежем ответе источника, после повторного импорта
      остаётся в базе без изменений (устаревшие коды никогда не удаляются).
- [ ] Поиск по началу названия находит коммуну независимо от регистра и
      диакритики («chateau» → «Château-Thierry»).
- [ ] Поиск по точному действующему коду INSEE возвращает ровно одну коммуну;
      запрос по коду с заполненным `effectiveTo` возвращает пустой результат.
- [ ] Коммуна с заполненным `effectiveTo` не появляется в результатах поиска.
- [ ] Запрос короче 2 символов отклоняется валидацией.
- [ ] Подсказки автодополнения ограничены 10 результатами и отсортированы по
      названию.
- [ ] Результаты поиска содержат название и département — одноимённые коммуны
      различимы.
- [ ] Поиск доступен без аутентификации.
- [ ] Тесты покрывают: импорт (идемпотентность, обновление названия), поиск
      (диакритика, регистр, код INSEE, одноимённые коммуны).
