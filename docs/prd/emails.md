# PRD: Письма приложения

**Дата**: 2026-08-02
**Статус**: approved <!-- draft → approved → done; в реализацию берётся только approved -->

## Цель

У продукта появляется способность доставлять письма: подтверждение veille,
уведомление о публикации arrêté, напоминания по шагам синистра. Ценность для
пользователя — письмо приходит на французском, из него понятно, почему оно
пришло, и из любого письма можно в один клик прекратить их получение.

Это фича-предпосылка: сама по себе она не даёт пользовательского сценария
целиком, но без неё не существует ни veille (`docs/prd/veille-subscription-lifecycle.md`),
ни уведомлений монитора JO, ни напоминаний синистра.

## Пользовательские сценарии

- Пользователь получает письмо от сервиса → видит понятного отправителя, тему на
  французском и текст, который читается даже если почтовый клиент не показывает
  картинки.
- Пользователь дочитывает письмо до конца → видит, почему оно пришло, и ссылку,
  которая прекращает получение писем.
- Пользователь получил письмо на адрес, который сам не оставлял → прекращает
  получение писем по ссылке из письма: одна кнопка на открывшейся странице,
  никаких данных вводить не нужно.
- Разработчик запускает приложение локально → письма не уходят на реальные
  адреса, но их содержимое и ссылки доступны, чтобы пройти сценарий целиком.

## В скоупе

- Единый механизм отправки транзакционных писем, которым пользуются все фичи
  продукта.
- Общий каркас письма: тема, имя и адрес отправителя, тело на французском,
  подвал с объяснением, почему письмо пришло, и ссылкой прекращения писем.
- Каждое письмо уходит в двух версиях — текстовой и HTML; текстовая содержит те
  же ссылки, что HTML.
- Локальный режим разработки: письма не уходят наружу, содержимое и ссылки
  доступны разработчику.
- Отказ отправки виден: вызывающий код получает ошибку, факт фиксируется в логе
  без адреса получателя.
- Настройка домена отправителя (аутентификация домена), подтверждённая ручной
  проверкой доставки в крупные почтовые службы.

## Не в скоупе

- Обработка недоставленных писем (bounce) и жалоб на спам, автоматическое
  удаление мёртвых адресов — отдельная итерация; вернуться, когда появится
  реальный поток писем.
- Очередь отправки с повторными попытками — появится вместе с монитором JO, где
  лаг ≤ 24 ч от публикации является требованием ТЗ § 6.
- Массовые и маркетинговые рассылки, дайджесты, настройки частоты писем.
- Языки, кроме французского.
- Вложения к письмам.
- Тексты конкретных писем: каждое письмо описывается в PRD своей фичи, здесь —
  только общий каркас и подвал.

## Ограничения

- Обработчик почты — в ЕС: адреса подписчиков не покидают ЕС (решение владельца
  02.08.2026, `docs/decisions.md`; RGPD).
- Email в логи не попадает ни на одном шаге отправки (ТЗ § 7).
- Ссылка прекращения писем — в каждом письме, в один клик, без промежуточных
  подтверждений. Для писем veille это требование ТЗ § 7; распространение на все
  письма продукта — решение владельца 02.08.2026 (`docs/decisions.md`).
- Переход по ссылке из письма сам по себе не меняет состояние: ссылка открывает
  страницу с единственной кнопкой, действие происходит по её нажатию — по
  ссылкам из письма ходят почтовые сканеры и превью (решение владельца
  03.08.2026, `docs/decisions.md`). Страницы за ссылками принадлежат
  фичам-владельцам писем, поэтому проверка «GET ничего не меняет» — в критериях
  готовности их PRD.
- Язык писем — французский; все строки в файлах локализации, в contracts
  текстов нет.
- Тексты рассчитаны на человека, впервые столкнувшегося с процедурой и
  в стрессе: административные термины (arrêté, CatNat) объясняются простыми
  словами при первом употреблении.
- Что именно означает «прекратить получение писем», решает фича-владелец
  письма (для veille — удаление подписки); каркас лишь обязывает такую ссылку
  иметь.

## Критерии готовности

- [ ] Отправленное письмо содержит тему, отправителя, текстовую и HTML-версии;
      набор ссылок в текстовой версии совпадает с HTML-версией.
- [ ] Каждое письмо содержит объяснение, почему оно пришло, и ссылку
      прекращения писем, доступную без аккаунта и без ввода данных.
- [ ] Попытка отправить письмо без ссылки прекращения писем завершается ошибкой,
      письмо не уходит: каркас не позволяет собрать письмо без такой ссылки.
- [ ] Email-адрес получателя не встречается в логах приложения ни при успешной
      отправке, ни при ошибке (проверяется тестом по перехваченным логам).
- [ ] При локальном запуске письмо не уходит на внешний адрес, а его текст и
      ссылки доступны разработчику.
- [ ] Отказ провайдера при отправке возвращается вызывающему коду как ошибка и
      фиксируется в логе; молчаливый «успех» невозможен.
- [ ] Все тексты писем и подвала — на французском, в файлах локализации; в
      contracts текстов нет.
- [ ] Письмо с настроенного домена приходит во «Входящие» Gmail и Outlook
      (ручная проверка, дата и результат зафиксированы в документации).
- [ ] Обработчик отправки размещён в ЕС; где обрабатываются адреса —
      зафиксировано в документации проекта.
