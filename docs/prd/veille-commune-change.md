# PRD: Veille — изменение состава коммун

**Дата**: 2026-08-02
**Статус**: draft <!-- draft → approved → done; в реализацию берётся только approved -->

## Цель

Наблюдатель, у которого уже есть подтверждённая подписка, меняет список коммун
(переехал, добавил коммуну родителей, ошибся при выборе) — не теряя подписку и не
проходя отписку с повторной регистрацией. Изменение вступает в силу только после
подтверждения по ссылке из письма: зная чужой адрес, изменить его подписку
нельзя.

## Пользовательские сценарии

- Подписчик заполняет форму тем же email с другим составом коммун → получает
  письмо со ссылкой подтверждения изменения; до перехода по ней подписка
  действует в прежнем составе.
- Подписчик переходит по ссылке подтверждения изменения → новый состав коммун
  вступает в силу, он видит подтверждение с перечнем коммун.
- Подписчик отправил изменение дважды → действует только последняя выданная
  ссылка, переход по прежней отвечает «lien invalide».
- Подписчик не подтвердил изменение за 7 дней → изменение отброшено, подписка
  продолжает действовать в прежнем составе.
- Посторонний, знающий чужой адрес, отправляет форму с этим адресом → состав
  коммун чужой подписки не меняется, а по ответу формы нельзя понять, был ли
  адрес подписан.
- Владелец адреса получает письмо об изменении, которого не запрашивал → в один
  клик по ссылке отписки удаляет подписку целиком.

## В скоупе

- Отложенное изменение состава коммун подтверждённой подписки: новый состав
  хранится до подтверждения и не влияет на рассылку.
- Double opt-in для изменения: письмо со ссылкой, страница результата.
- Действует только последняя выданная ссылка изменения; прежние отвечают
  «lien invalide».
- Срок жизни ссылки изменения — 7 дней; по истечении изменение отбрасывается, а
  сама подписка сохраняется в прежнем составе.
- Ссылка отписки в письме об изменении удаляет подписку целиком, включая
  неподтверждённое изменение.
- Замена поведения из `docs/prd/veille-subscription-lifecycle.md`: повторная
  отправка формы существующим адресом теперь запускает изменение состава, а не
  присылает письмо «вы уже подписаны».

## Не в скоупе

- Изменение самого email подписки — отписка и новая подписка.
- Частичное изменение (добавить/убрать одну коммуну отдельными действиями) —
  форма всегда задаёт полный состав.
- История изменений состава подписки.
- Уведомление о том, что состав изменён, на прежний состав коммун.
- Личный кабинет наблюдателя.

## Ограничения

- Изменение состава — тоже double opt-in: зная чужой email, менять его подписку
  нельзя (`docs/research/data-model.md` § 6).
- Ответ формы одинаков для нового адреса, подписанного адреса и адреса с
  неподтверждённым изменением (анти-enumeration).
- Лимит писем на адрес в сутки и лимит 20 коммун на подписку — те же, что в
  `docs/prd/veille-subscription-lifecycle.md`.
- Срок жизни ссылки изменения — 7 дней: продуктовое решение владельца
  (02.08.2026), не юридический срок, SourceReference не требуется.
- Отложенный состав коммун моделью данных не предусмотрен
  (`docs/research/data-model.md` § 6 описывает только действующий состав) —
  отступление зафиксировано в `docs/decisions.md` (02.08.2026); конкретную форму
  хранения выбирает research этой фичи, модель данных правится в том же коммите.
- Удаление подписки сносит и неподтверждённое изменение — hard delete каскадом
  (ТЗ § 7, RGPD).
- Email не попадает в логи; язык интерфейса и писем — французский, строки в
  локализации.
- Зависимость: `docs/prd/veille-subscription-lifecycle.md` реализован.

## Критерии готовности

- [ ] Отправка формы существующим подтверждённым адресом с другим составом
      коммун не меняет действующий состав до перехода по ссылке.
- [ ] Переход по действующей ссылке изменения применяет новый состав целиком:
      коммуны, которых нет в новом составе, перестают отслеживаться.
- [ ] После повторной отправки формы действует только последняя ссылка
      изменения; переход по любой из прежних отвечает «lien invalide».
- [ ] Неподтверждённое изменение старше 7 дней отбрасывается: подписка не
      удаляется и продолжает действовать в прежнем составе, а ссылка изменения
      отвечает «lien invalide».
- [ ] Ответ формы неразличим для нового адреса, подтверждённой подписки и
      подписки с неподтверждённым изменением.
- [ ] Ссылка отписки из письма об изменении удаляет подписку и неподтверждённое
      изменение немедленно, одним кликом.
- [ ] Неподтверждённое изменение не влияет на рассылку: в расчёт получателей
      берётся только действующий состав (проверяется на данных, без отправки —
      сама рассылка в PRD монитора JO).
- [ ] Изменение с 0 коммун или более чем 20 коммунами отклоняется валидацией;
      действующий состав при этом не меняется.
- [ ] Email не встречается в логах приложения ни на одном шаге сценариев выше.
- [ ] Страница результата подтверждения изменения проходит axe без ошибок и
      проходима с клавиатуры.
- [ ] Все пользовательские строки — на французском, в файлах локализации.
