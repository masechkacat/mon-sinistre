# Пивот Jalons: с цикла MDPH на catastrophe naturelle (CatNat)

Дата решения: 30.07.2026. Статус: принято (Марина: «стартуем»).

## Почему уходим от MDPH

Официальный портал mdphenligne.cnsa.fr закрыл ядро исходной ценности: он сам считает даты
следующего продления, присылает email-напоминания и хранит решения MDPH в личном кабинете.
Конкурировать ручным вводом дат с бесплатным госсервисом, встроенным в саму подачу, —
проигрышная позиция. Исходное ТЗ эпохи MDPH удалено 30.07.2026 по решению Марины
(доступно в git-истории); новое ТЗ написано на том же месте —
`docs/technical-specification.md`.

## Новая ниша

Режим catastrophe naturelle: возмещение ущерба возможно только после публикации
межминистерского arrêté в Journal Officiel, у пострадавшего **30 дней с даты публикации**
на декларацию страховщику (режим CatNat; в новом ТЗ зафиксировать точную норму кода
страхования со ссылкой — SourceReference). Персонально о публикации никто не уведомляет
(префектура → мэр → «информирование жителей»). Конкурентная разведка (30.07.2026, три
агента + проверка Марины): связку «мониторинг arrêté + ведение процесса + контроль
юридических сроков» не делает никто — страховщики начинают после декларации,
generic-приложения не знают французского права, юристы приходят на конфликт.
Отдельная боль — **отказы** (annexe II arrêté): о них тоже не уведомляют, а от них идёт
срок оспаривания.

## Продукт (MVP)

1. Подписка на коммуны → email в день публикации arrêté (признание **и** отказ).
2. «У меня синистр» → 30-дневный план: чек-лист по дням, дедлайн декларации, напоминания.
3. Инвентарь ущерба: предмет, стоимость, фото, чек, даты.
4. Сроки страховщика после декларации (эксперт, выплата) — каждая цифра с SourceReference.

Отложено в v1.x: генерация писем страховщику, PDF-экспорт досье, push (сначала email),
геометки фото, журнал relances как модуль.

## Что переиспользуем из кодовой базы

- Монорепозиторий, contracts → api → web, NestJS+Fastify+TypeORM, Next.js, env-валидация,
  rate limiting, pre-commit — без изменений.
- Ядро домена: «опорная дата разворачивает план шагов со смещениями, статусы вычисляются
  на чтении, напоминания по порогам», `IsoDate`, `SourceReference`, копия плана в досье.
  Опорная дата теперь — публикация arrêté (было — истечение прав).
- Требование WCAG 2.1 AA / RGAA 4.1.2 сохраняется в полном объёме (аудитория в стрессе,
  много пожилых; déclaration d'accessibilité — конкурентное отличие: 0 из 6 разведанных
  соседних сервисов её имеют).
- Запрет медицинских данных теряет актуальность (фото ущерба — не меддокументы), но
  принцип минимизации данных в логах сохраняем.

## Источники данных — проверено прототипом 30.07.2026

1. **DILA open data JORF** (`echanges.dila.gouv.fr/OPENDATA/JORF/`) — первичный источник.
   Без авторизации. Суточные дельты-тарболы (~2/день, сотни КБ – единицы МБ).
   Проверено: arrêté NOR INTE2615534A, опубликованный в JORF n°0137 от 13.06.2026,
   присутствует в ночной выгрузке `JORF_20260613-010126` → **обнаружение в день публикации**.
   Приложения парсятся из XML в структуру: département / commune / risque / период /
   мотивировка; annexe I (признанные, 161 коммуна в тестовом arrêté) и annexe II (отказы)
   различимы. ВАЖНО: дельты пересылают изменённые тексты повторно (тот же NOR встретился
   в выгрузке от 17.07) → дедупликация по NOR, дата публикации — только из XML
   (`DATE_PUBLI`/номер JORF), никогда — из даты появления файла в выгрузке.
2. **Géorisques API** (`georisques.gouv.fr/api/v1/gaspar/catnat`) — история CatNat по
   `code_insee`, без авторизации. Годится для онбординга («история вашей коммуны») и
   перекрёстной проверки. **Не годится как источник дат**: в тестовой записи
   `date_publication_jo` = 12.06.2026 при реальной публикации 13.06.2026 (ошибка в 1 день
   недопустима при 30-дневном сроке).
3. **geo.api.gouv.fr/communes** — резолюция названия коммуны в код INSEE, без авторизации.

Ни один источник не требует ключей/регистрации; PISTE/Légifrance API не нужен для MVP.

## Позиционирование и ограничения

Как и в эпоху MDPH: сервис не даёт юридических консультаций и не взаимодействует со
страховщиком от имени пользователя — он следит за сроками и ведёт досье. Все справочные
сроки — со ссылкой на источник и датой сверки.
